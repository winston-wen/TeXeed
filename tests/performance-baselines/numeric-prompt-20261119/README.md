# 数字写法、显式公式及排版开销（2026-11-19）

同一台 Windows 10.0.26300、WindowsDesktop 10.0.7 主机，使用独立项目及配置，Release WPF 窗口位于屏幕外、保持未激活。各版本复用同一测量宿主。每项预热两次，报告七组样本的中位数。首次反馈计至 ApplicationIdle。排队校正将后续 800 ms 等待、适用的公式任务与保存锁纳入工作样本，再减去相邻空操作的耗时或 UI 线程分配。可见控件按与窗口相交估算，公式图形另计全部已创建的控件。

## 三种输入与显示

同一份 30 段回答有五个标题，源码中每段都写“输出 `$0$` 或 `$1$`，由算法 `$D$` 检查”，末尾有一道行间公式。0.5.20 和 0.5.21 用同一文件内容比较两版对显式公式的处理。此外，在同一 0.5.21 程序内单独测量提示词建议的写法：只把这段源码的 `$0$`、`$1$` 换成 `0`、`1`。文字内容、四个追问气泡、合成 SVG 热缓存、渲染路径、窗口宽高和场景均相同。这个对照测量已得到这两种文本时的排版开销，未测模型服从提示词的概率。

- 混排按实际渲染结果验收。把两处数字写成普通文字时，文档应能连续读出 30 处“输出 0 或 1”，另有 30 个 D 和一道行间公式。写成显式数学的旧回答在 0.5.21 中应创建 91 个成功加载 SVG 的公式。每次取样结束后核对两项计数。
- 常态夹具含 120 轮，测草稿输入、窗口宽度交替、跨轮滚动与改变主编辑框高度。标题密集夹具含 24 个标题和 24 段中英文混排，测折叠展开及变宽变窄。

两版提交同一批带美元符的文本。0.5.20 的 21 个混排样本均为 31 个公式图形、30 对正文数字，0.5.21 的 21 个样本均为 91 个公式图形、0 对正文数字。恢复 60 个显式公式后，全文重排和调整宽度分配分别比 0.5.20 多 1,211,944 和 820,672 B。与同样保留 91 个 SVG 的 [0.5.19 复测](../inline-baseline-20261119/before-mixed.json) 相比，0.5.21 在全文重排、调整宽度、气泡替换上分别少 96,016、74,976 和 31,376 B。

常态会话的四项可见控件均保持 47 个，跨轮滚动分配中位浮动 32 B，另外三项持平。标题密集回答的宽度调整分配持平。折叠展开的中位多 10,424 B，七对样本中三对零差，另两对在首次反馈前相同、排队校正后各差 11,808 B，其中一对完全来自配对空操作。各对的最终回答高度相同。夹具只含普通文字及数字，未采分配调用栈，尚未完整归因。

## 复测

使用上一版的 [混排夹具与检查补丁](../inline-baseline-20261119/README.md)、[常态夹具](../manual-form-unlock-20261118/panel-fixture.cs.txt)、[标题夹具](../chat-font-size-20261119/fixture.cs.txt) 及 [WPF 测量宿主](../annotation-modes-20261118/Harness.csproj)。对保留 `$` 的源文，0.5.20 传 `decimal-text`，0.5.21 省去该参数。对 0.5.21 的裸数字源文，只替换混排夹具中的固定片段“输出 `$0$` 或 `$1$`”，其他字符保持原样，重新编译测量宿主并传 `decimal-text`。该参数仅校验测量后的文字和控件，不改变渲染行为。所有样本的界面输入均由原生控件处理。
