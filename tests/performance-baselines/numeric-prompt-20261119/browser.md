# 浏览器显式数字公式

50 轮回答共含 300 个标题、900 个用数学定界符包住的数字和 300 个代数式。三个版本读取相同的 Markdown。测量在 Windows 10.0.26300 上运行，使用 Chrome 157.0.8103.79、Node 24.22.3 和 1000 × 820 CSS 像素视口。三批交错测量，每批预热两次，取七次计时的中位数，再取三批中位数。[逐次样本及资源指纹](browser-samples.json)

| 指标 | 0.5.19（12b1077） | 0.5.20（7826358） | 0.5.21 |
| --- | ---: | ---: | ---: |
| 首次重建（ms） | 181.8 | 119.7 | 192.5 |
| 热重建（ms） | 147.2 | 97.9 | 173.2 |
| 含延后更新的校正耗时（ms） | 168.3 | 92.8 | 199.0 |
| V8 抽样保留堆（B） | 276,084 | 226,920 | 249,848 |
| 公式树 | 1,200 | 300 | 1,200 |
| 页面元素 | 19,443 | 9,544 | 19,443 |
| 控件总数／视口内控件 | 441／27 | 441／28 | 441／28 |

0.5.20 将其中 900 个带定界符的数字显示为文字。0.5.21 按源码恢复这些公式的 TeX 字形、复制与引用。相同源码下，热重建比 0.5.20 多 75.3 ms，比同样显示 1,200 个公式的 0.5.19 多 26.0 ms。本样本可直接核对前者增加的 9,899 个页面元素，无法单独解释后者的时间差。V8 每 1,024 B 抽样一次，此列只估计保留在堆上的对象。队列耗时包含两个动画帧及 200 ms 的延迟更新窗口，并扣除实测空等待。本夹具没有裸写数字的对照组。

在仓库根目录执行以下命令可复测。

```powershell
node tests/performance-baselines/chat-font-size-20261119/browser-measure.cjs --history 12b1077 --baseline 7826358 --fixture tests/performance-baselines/inline-baseline-20261119/browser-numbers-fixture.cjs --output artifacts/browser-numeric-prompt.json
```

## 打开会话关系标签

另一组样本使用 120 轮、60 个分支，沿用[打开关系图夹具](../branching-reading-20261110/branch-operations-sampled.cjs)的 `map` 操作，分别加载 0.5.20 和 0.5.21 页面。预热两次后测七对空操作和打开操作，并将两帧和 220 ms 的延后工作计入。两版同步耗时中位数为 1.3／1.1 ms，校正耗时为 0.3／1.9 ms，净抽样分配为 215,352／212,840 B，视口内均有 16 个控件。七对样本中的排队耗时随帧相位波动。新版少一个 DOM 节点，切换时整体隐藏会话区域及其状态栏。[本版逐对样本](relations-browser-samples.json)

同夹具早期记录的同步中位数为 1.3 ms，校正耗时为 −0.5 ms，净抽样分配为 232,632 B，可见控件 13 个。早期原型功能、Node 和 Chrome 的补丁版本与本次不同。[早期原始记录](../branching-reading-20261110/branch-operations-final.json)
