# 会话关系图与追问链接性能（2026-11-11）

同一 Windows 11 机器、.NET SDK 10.0.203、WPF 900×760 DIP，所有样本顺序运行，不与其他桌面测试并发。每项预热两次，记录七次，配对扣除相邻 ApplicationIdle；常规 120 轮夹具还等待 800 ms 草稿保存及保存锁，并扣除相邻空等待。只计算 UI 线程托管分配与窗口内相交的可见控件，不包含后台线程、GPU、真实输入法和物理鼠标。样本均为单批，不能把耗时小幅变化视为稳定结论。

## 关系图打开、滚动与键盘选择

`graph-fixture.cs.txt` 在真实 MainWindow 中构建 120 或 500 个同一父会话的子会话。对每个版本分别预热两次、打开七次，最后一次打开后再测两次预热和七次交替滚动、上下键选择；打开和滚动均与相邻 Idle 配对。此夹具覆盖完整工作区，历史 `native-branches-20261110/deep/` 的 120 子会话记录为独立弹窗约 3.43 MB／65–66 ms、25 可见控件，统计窗口不同，不可直接作为本表的同场景历史最佳；表中的 0.4.5 是当前可复核的同场景暂定基准。旧树的合成方向键事件未被处理，不能把其选择数字当有效对照。新图与旧树展示和节点控件不同，可见控件差异包括功能形态。

## 长回答新建追问与折叠

`folding-fixture.cs.txt` 在已加载父会话的一篇约 60 段、每段约 180 字的回答上，保留父窗口不切换，预热两次后连续测七次从同一位置新建追问（含隔离目录内异步保存和 Idle），然后各测九次折叠再展开。0.4.5／当前功能构建分别为新建追问 160,448／2,680,912 B、16.46／44.30 ms，控件 27／33；折叠展开 4,791,376／5,122,920 B、85.99／87.65 ms，控件 27／36。旧版未即时在父回答显示链接，因此并非同功能比较。

`folding-reason-fixture.cs.txt` 针对相同视口功能 DLL 以无插链／正常插链／正常插链／无插链顺序交错四批，反事实通过清空已加载回答的 layer 集合，阻止父会话即时插入链接，仅用于归因，不具备产品功能。无插链两批为 160,448 B、15.59–15.98 ms、27 控件；正常插链两批为 2,680,912 B、46.34–48.03 ms、33 控件，稳定差额约 2,520,464 B／30 ms，涉及不断增加的多个实际链接、文字定位和 WPF 排版。该方法未提供调用栈，无法将差额完整拆分为必要功能成本和可避免实现开销；每次新建后会保留已有链接，测量中位处已有约六个链接。样本 `no-link-a/b.json`、`link-a/b.json` 为原始记录。

## 复测

将各 `*-fixture.cs.txt` 内容编译为 .NET 10 Windows WPF WinExe，引用对应 TeXeed 与 TeXeed.Core 程序集并复制对应版本的依赖；使用独立输出目录，其下 `TEXEED_HOME` 由夹具自动隔离。图夹具第二参数为子会话数，反事实夹具第二参数为 `suppress` 时禁用即时插链。避免并行运行其他 UI 测试，并记录实际 DLL 哈希与物理显示环境。
