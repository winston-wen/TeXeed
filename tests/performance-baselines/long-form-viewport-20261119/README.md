# 长答框跨轮视口修复性能（2026-11-19）

同一 Windows 10.0.26300、WindowsDesktop 10.0.7 主机在隔离设置和项目中运行 Release 程序。WPF 窗口位于屏幕外且不激活。每项预热两次、采七对样本。首次反馈计至 ApplicationIdle，随后等待 800 ms、草稿保存计时器与保存锁，并和同批空操作配对校正耗时和 UI 线程分配。可见控件按与窗口相交统计，未完全扣除祖先裁剪。WPF 调度会使反馈及校正耗时波动，负值只表示小于相邻空操作。

- [常态视口夹具](../manual-form-unlock-20261118/panel-fixture.cs.txt) 用 120 轮会话，在 900×760 与 620×760 DIP 间改变大小，测草稿输入、滚动与主编辑框增高。历史基准取 [两个历史构建的同机重测](../chat-viewport-20261119/README.md) 及 [此后同条件复测](../ai-reading-axis-20261119/README.md) 各项较小值。
- [长答框夹具](../multiline-form-20261119/fixture.cs.txt) 在 120 轮会话的第 61 轮设置长答框，前有 25 段、后有 38 段。用 900×760 DIP 窗口将答框定位于 Y=180 DIP 后，追加、删除、在固定宽度下输入自动折行的文本，或触发框内滚轮路由事件。夹具用未取得焦点的文本框执行实际编辑与草稿保存路径。它记录操作结束时答框和前文屏幕位置。带焦点连续增减行的逐帧位置及相邻轮边界由 [原生专项](../../TeXeed.AppTests/AiLongFormViewportTests.cs) 验证，未纳入本性能夹具分配采样。

长答框的 0.5.16 和 0.5.17 原始样本见 [八行上限性能](../multiline-form-20261119/README.md)。0.5.16 无八行封顶，滚轮滑动整篇会话，折行及缩减的分配因旧行为而更低。0.5.17 已有八行及内部滚动。0.5.18 正式发布程序集为本次直接改前基准。

表中顺序为有八行上限及内部滚动的历史构建较小值、正式 0.5.18、0.5.19 功能构建。三列使用相同夹具、宽度和保存路径。历史列取 0.5.17 两个可复核构建逐项较小值，校正计时取最小正值。

与改前相比，四项分配中位分别少 1,408、1,136、2,656、4,480 B。与同功能历史相比，四项分配均下降，删行、折行和滚轮的首次反馈中位仍高于历史较小值。候选的估计可见控件数各少 18 个。统计未扣除祖先剪裁，未分拆减少的是哪些控件。

增删和折行后仍保留八行上限，内部滚轮每次推进 48 DIP。每项七对样本中，答框和前文标记在操作结束后的实际坐标位移均为 0 DIP。候选在增行、删行和折行时报告的外层偏移变化中位为 270、−270、653.4 DIP，正文和操作位置保持原位。0.5.16 的四项分配依次为 856,360、691,592、646,352、355,600 B。减行和折行的较低值随无八行上限及内部滚动的旧行为出现，已有 [单独关滚动条的对照](../multiline-form-20261119/README.md) 支持这一差异。 [改前样本](before-field.json) · [改后样本](after-field.json)

## 复测

用 [原生测量宿主](../annotation-modes-20261118/Harness.csproj) 以 Release 编译相应夹具。将 `ProductDir` 指向完整应用目录，`Fixture` 指向夹具的绝对路径。将宿主生成的 `TeXeed.AppTests*` 复制进各独立完整应用副本，核对程序集、宿主和夹具指纹，再运行 `dotnet TeXeed.AppTests.dll <隔离输出目录>`。
