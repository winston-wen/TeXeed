# 批注浮窗原生性能（2026-11-12）

同一 Windows 主机、.NET 10.0.7、Ristretto 深色主题和 2 倍 DPI 的 WPF 隔离宿主；使用 `fixture.cs.txt` 的一条合成批注，在 680×620 DIP 窗口分别测浮窗打开和“完成并关闭”。每版各两批，每批预热 2 次、采样 7 次；每次与相同 ApplicationIdle 排队及 250 ms 等待的空操作配对，记录即时反馈、扣除等待后的耗时、UI 线程分配与可见控件。浮窗只做内存中的确认／保存回调，不包含真实磁盘保存、用户鼠标、图片或模型请求。两个按钮及输入框在浮窗视图中，控件数按 WPF IsVisible 和非零尺寸估计；Popup 另行计数，未扣祖先裁剪。

打开浮窗的配对分配中位：改前 `340,416 / 339,680 B`，新版 `361,752 / 358,024 B`，新版比改前增加约 `21,336 / 18,344 B`；可见控件两版均为 9。即时反馈分别为 `17.34 / 14.67 ms` 与 `14.81 / 14.11 ms`，等待校正后的中位分别为 `15.41 / 17.85 ms` 与 `20.62 / 22.07 ms`，两批不足以确认小幅耗时变化。确认并关闭的分配为改前 `28,960 / 22,616 B`、新版 `27,216 / 29,112 B`，波动较大，关闭后均为 4 个可见控件。此浮窗夹具此前无同方法、同环境的可复核历史最佳；改前是本次同场景暂定基准。

深评使用基于新版的隔离反事实：保留其它实现和点击处理，只移除“完成”文字及其额外布局（见 `no-label-control.patch.txt`），打开浮窗为 `341,928 B`、9 个控件。相比完整新版约少 `16–20 KB`，接近改前；差额涉及新增文字及 WPF 布局。此反事实没有所需文字，改变了按钮尺寸，且无调用栈与同外观替代实现，不能据此断言差额全部不可避免或确定每项可避免开销。它只测一批，仍需复测。此项目列出分配增量和未分离成本，不以未达到报警阈值认定全面通过。
