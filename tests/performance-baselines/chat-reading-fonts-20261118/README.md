# AI 阅读字体性能（2026-11-18）

测试使用隔离项目、屏幕外且不激活的 WPF 窗口，不读取用户会话。常态测试沿用 `../manual-form-unlock-20261118/panel-fixture.cs.txt` 的 120 轮、每轮三条 200 行过程记录；测试输入、窗口变宽、滚动和编辑框高度。每项两次预热、七次采样，并配对 800 ms 空队列、草稿保存计时器、保存锁及 `ApplicationIdle`。旧有历史最佳与完整条件见 `../unlock-viewport-20261118/README.md`。

`mixed-math-fixture.cs.txt` 在 900/620×760 DIP 的独立 Markdown 阅读视图中使用 30 段中文、英文与数字，包含 Il1、O0、90 个行内公式及一个行间公式。测试重排和窗口变宽；复制 `../quote-scroll-20261116/math-svg/` 的合成 SVG 热缓存到隔离配置，不触及用户数据。每次等待正文及当前公式任务完成，配对 800 ms 空等待并记录反馈耗时、UI 线程分配、可见控件和公式元素数。它不测公式冷编译、GPU 或物理键鼠；可见控件数以窗口矩形估算，未扣除祖先裁剪。独立夹具没有更早同场景历史最佳。

对照使用用户提供的本机冬青 W3 字体文件和随程序提供的 IBM Plex Sans Regular；旧版不使用这两种阅读字体。测试前核对字体文件、程序和宿主指纹；新字体及中英文混排本身是功能差异。两版须串行运行，不与其他构建、测试重叠；负的校正时间表示波动，不表示负耗时。

复测以 `../annotation-modes-20261118/Harness.csproj` 为宿主工程，`ProductDir` 指向测试版本的完整依赖目录，`Fixture` 指向相应 `.cs.txt` 的绝对路径。将同一构建出的宿主文件放入各版本的独立完整运行目录，核对 `TeXeed.dll` 和字体资源后，依次运行 `TeXeed.AppTests.exe <独立输出目录>`；混合公式夹具再传入 `../quote-scroll-20261116/math-svg/` 的绝对路径。性能仅衡量功能构建；正式发布程序集需另行核对。

## 主对照结果

同一 Windows 10.0.26300、WindowsDesktop 10.0.7 主机运行，字体专项使用 Ristretto 主题；屏幕外窗口不会抢占前台。`fingerprints.json` 保存两版程序集、字体、宿主及夹具的 SHA-256。候选文字通过实际 WPF GlyphRun 验证：拉丁字形来自 IBM Plex Sans Regular，中文字形来自冬青 W3，`ss04` 仅改变样本中的零字形；无用户路径或字体文件进入性能记录。被测冬青文件与用户样本的 SHA-256 均为 `94800E331A3DDDE3BB8C0CC14713FB8F7E6884AD275A850FBB408AC9D129132B`。

普通 120 轮会话中，正式 0.5.13／候选的输入、变宽、滚动和编辑框高度 UI 线程分配中位依次为 262,128／262,128、853,624／867,784、190,200／189,544、116,128／116,128 B；首次反馈为 3.41／3.21、20.94／15.72、1.09／1.17、3.06／3.05 ms；排队校正耗时为 −0.73／−0.05、15.66／16.00、−1.36／0.23、−1.18／−2.10 ms。两版各一批，均 47 个可见控件；小幅耗时差和负值受调度影响，不能视为稳定提速。变宽七次按顺序相减分别增加 14,160、11,024、14,160、11,024、14,160、11,024、14,160 B，增量稳定，须进一步核查。

同夹具可复核历史最小分配依次为 253,864、550,296、176,328、108,584 B；对应样本分别可查 `../ai-docked-composer-20261110/history-verified.json` 的输入与滚动，以及 `../context-branch-ui-20261110/native-after.json` 的变宽与输入框高度。对应首次反馈为 3.06、18.94、0.83、3.08 ms，排队校正为 −0.85、16.26、2.86、1.99 ms；相应控件数为 40、41、40、41。历史样本在可见窗口、不同运行环境中采集，旧版缺少部分后续功能，差额不全能归因本次修改，也不能用作本次同条件最佳。原始对照在 `before-panel.json` 和 `after-panel.json`。

中英文与公式视图的重排／变宽分配中位旧版为 6,574,680／4,838,232 B，候选为 6,676,936／4,839,792 B；首次反馈 28.92／22.56 与 23.82／21.99 ms，校正耗时 27.83／18.98 与 16.77／16.69 ms，均 2 个可见控件和 91 个公式。重排七次差值为 +108,232、+100,024、+104,544、+98,992、+99,552、+111,464、+105,712 B；稳定增量约 99–111 KB，两个功能版本的排版实现和所选字体不同。该夹具没有更早相同场景的可复核历史最佳；原始样本为 `before-mixed.json` 和 `after-mixed.json`。

## 反事实深评

为排查稳定分配增量，均使用同一候选程序集及同一宿主，按 A→B→B→A 串行交错，每批两次预热及七次采样。B 为只供分析的反事实，不能作为交付字体：

1. 只测变宽时，A 为实际字体，B 暂时把已显示阅读正文覆盖成旧版字体、关闭其 `ss04`。A1／B1／B2／A2 的分配分别为 819,264／819,208／819,208／819,264 B，均 47 控件；此前未执行主对照中的输入操作，因此不与主对照数值直接相减。
2. 按主对照先执行九次输入再测变宽，A1／B1／B2／A2 分别为 867,784／867,728／867,728／867,784 B，均 47 控件。原先的 +11–14 KB 在 B 中仍存在，表明仅换回正文族和关掉正文特性不足以解释该增量；它不排除未覆盖区域的功能成本或实现开销。
3. 保留实际字体，仅将 History 容器上的 `ss04` 继承开关切换，其他 Markdown 正文自身设置保持不变。输入后变宽 A1／B1／B2／A2 分别为 867,784／867,728／867,728／867,784 B，均 47 控件；容器开关本身只对应约 56 B，仍不能解释主对照的差额。
4. 中英文公式重排视图中，A 为实际阅读字体，B 覆盖为旧正文族。A1／B1／B2／A2 分别为 6,679,912／6,681,120／6,681,120／6,679,912 B，均 2 控件和 91 个公式；仅改变字体没有消除主对照约 99–111 KB 的差额，说明不能简单将其视为字形选择本身的成本。
5. 相同字体下对照 `ss04` 开／关，A1／B1／B2／A2 重排分配为 6,679,912／6,748,584／6,748,584／6,679,912 B。B 在文档创建后将已经开启的属性再改为关闭，会额外触发属性传播；其多出的约 68 KB 不能视为关闭特性的真实成本，也不能由此推断 `ss04` 的必要成本。

上述深评在相同候选版本内分别改变部分因素，排除了“只由正文族”或“只由 History 继承开关”解释主对照增量；它没有调用栈，也未对所有新增布局与属性传播逐项做同功能反事实。因此 11–14 KB 变宽增量与约 99–111 KB 重排增量中的功能成本和可避免实现开销尚未完整拆分，不能宣称本轮性能验收全面通过。反事实源码、逐次样本和程序集／宿主指纹分别为 `counter-*.json`、`counter-*-fingerprints.json` 及对应的 `*-counterfactual.cs.txt`。

## 执行与失效样本

在已提供本机冬青文件、两份应用依赖完整、确认没有其他构建或桌面测试时，使用 `run.ps1 -Before <已发布版本目录> -After <候选目录> -Output <artifacts 下新目录>` 串行执行主对照。`-OnlyMixed -PanelRun <上一次运行目录>` 用于只重采混合正文，并要求先前与本次程序集哈希一致。`run-counterfactual.ps1 -Product <候选目录> -Output <artifacts 下新目录>` 复测步骤 1、4，添加 `-AfterInput` 复测步骤 2；步骤 3 用 `run-history-counterfactual.ps1`，步骤 5 用 `run-feature-counterfactual.ps1`。所有脚本先校验实际产品与字体哈希。反事实只用于度量，不能替代最终产品的字形验收。

首轮混合夹具在 WPF Dispatcher 启动前创建公式，异步回调因错误线程失败，记录在 `invalid-before-mixed-error.txt`；修正为窗口 Loaded 后创建。第二轮旧版有效，候选原先用 `FormattedText` 的完整路径字符串比较独立与混排字形，受基线与布局位置影响失败，记录在 `invalid-after-mixed-geometry-error.txt`；该判据已换成实际 GlyphRun 字面与 `ss04` 字形编号检查，并以同一修正后宿主重采两版。上述失效样本均不纳入结果。
