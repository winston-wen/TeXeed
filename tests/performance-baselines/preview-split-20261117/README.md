# 多预览分区性能对照

Windows 10.0.26300、.NET WindowsDesktop 10.0.7、用户 DPI 192；相同 1200×800 DIP 的屏幕外、不激活窗口，两份各 120 段合成源码，Tectonic 编译。由原来的 `../multi-entry-20261109/fixture.cs.txt` 仅将窗口位置改为屏幕外并设 `ShowActivated=false`，以免抢占用户当前工作；每项预热两次，采七次，逐次配对空 ApplicationIdle 调度，记录耗时、UI 线程分配及可见控件。预览切换不等异步页面栅格化，控件数按窗口相交计算且不检查祖先裁剪。

`before.json` 为正式 0.5.6（提交 `c5d7bf5`）测得的原始样本，程序集和夹具指纹在 `before-fingerprints.json`。此条件与历史夹具的可见窗口及 .NET 10.0.14 不同，不能直接将历史数值当作可比较的性能验收基准；历史可复核样本仍见 `../multi-entry-20261109/`。新建分区是新增功能，没有同功能旧版历史成绩。

复测时以同一 `fixture.cs.txt` 构建 .NET 10 Windows WPF 宿主，引用对应版本的 `TeXeed.dll` 和 `TeXeed.Core.dll`，运行时放入同版本发布目录，传入结果目录、固定合成项目路径、仓库根目录。需使用相同系统 DPI 与后台条件，并保证 `.tools/tectonic/tectonic.exe` 和缓存可用；不要与其他构建或桌面基准同时运行。

`after.json` 是提交前功能构建的旧有切换操作对照，`split.json` 是相同功能构建中反复创建和合并右侧预览区的专项；其夹具为 `split-fixture.cs.txt`，并保存程序集及夹具指纹。创建前两份预览在同一组，创建后分别显示；合并后恢复到原组。新操作没有旧版同功能对照，配对空闲只覆盖 ApplicationIdle 前的调度，未包含异步 PDF 栅格完成或真实鼠标拖拽。七次结果为独立样本，不能将一次采样视为稳定结论。功能构建不是最终提交后重建的发布程序集。

0.5.6／本次功能构建的源码切换中位数为 58.79／41.31 ms、4,184,448／4,177,856 B；预览切换为 31.11／3.93 ms、153,968／99,280 B；可见控件均为 50。新版本保留每个预览的独立控件，预览切换路径和生命周期不同；各一批且计时波动较大，不能据此推断稳定提速。分区创建／合并各一批的中位数为 52.15／70.38 ms、4,702,272／7,252,824 B，分别为 62／50 个控件。创建过程包含新增区域和两个预览同时布局，合并包含重组界面；七次分配都为正且数量明显，但缺少调用栈和同功能反事实，无法拆分必要功能成本与可避免的实现开销。

优化前中间构建的 `split-before-optimization.json` 分别为 60.36／64.49 ms、4,720,824／7,259,856 B；其间还修改了编译中的预览选择，且中间构建未保存完整源码快照，不能作为可复核的历史最佳，也不能将差异全部归因于刷新优化。最终 0.5.7 功能程序集 SHA-256 为 D585103F191D4CAD7E0B47E03ABC804BB7229A13BA999F6124A098E6EDF42A18；嵌入的源码版本仍为旧提交 c5d7bf5，发布提交后会变化。
