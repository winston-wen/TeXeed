# AI 可填写控件与 Emoji 原生性能（2026-11-12）

## 环境与方法

同机 Windows 10.0.26300、Ryzen 7 5700X、.NET WindowsDesktop 10.0.7；隔离配置、Release、900×760 DIP WPF 窗口。常态对话沿用 `../steering-20261112/panel-fixture.cs.txt`：120 轮、每轮 3 条各 200 行过程记录，每项预热两次并采七次；操作前后等待相邻空 ApplicationIdle、800 ms、草稿计时器和保存锁，并配对校正。可见控件按窗口矩形与实际可见性估计，未完全扣除祖先裁剪。每次样本及实时反馈、等待校正后的耗时与 UI 线程分配分别记入 JSON；不包含后台线程、GPU 和真实键盘输入。

`before.json` 为本次改前 `a07ec4c5483bcab3c6cdb5c6606aa14ff86f0678` 的独立源码构建；TeXeed.dll SHA-256 `D6F108974938F5F68500720C7B0A643B3720026061677707497F716FC482E0FB`。常态夹具 SHA-256 `A52DB958492CAF50D84BAC50BEE5131F98CEEDF093C490392A8C56D91099C95D`。历史最佳参考 `../ai-docked-composer-20261110/` 与 `../context-branch-ui-20261110/`，旧版缺少后来书签、会话关系等功能；历史记录的运行时版本标注与本次 10.0.7 不完全一致，数值只作参照，不能把差额全部当作本次退化。改前与本次各一批、不是交错重复；等待校正值有明显调度波动，不能以负数或少量差异排序。

中间版 `forms-intermediate-fixture.cs.txt` 使用相同的 120 轮对话，将最后一轮换成 6 行、18 个单行文本框的表格，另有多行、2 个单选和 1 个多选；分别测更改表格字段、变宽、滚动和输入框高度。字段值通过属性设置，不覆盖真实输入法；表单是新增功能，历史版没有同功能对照。中间版夹具 SHA-256 `CBD68F2CD38B12F8FC3EA2FE5B8224C84C7A799F773346E50E9CFAD30DC92763`。

`emoji-fixture.cs.txt` 的同一 MarkdownView 依次排版 50 段普通中文、加 1 个 emoji、加 60 个 emoji；各记录首次冷排版和 2 次预热后的七次热排版，并与相邻 ApplicationIdle 配对。旧版用系统字体，新版用 Noto 图片，功能不同；同一 emoji 重复时不代表全不重复内容。私有内存是整个进程瞬时差，可能包含非 emoji 工作；图像计数是 WPF 可见 Image，不等于 GPU 内存。夹具 SHA-256 `498B3B5192E1C97806B67485297294C1CEBF55FAA3CF4FA799DB5B9E1FB1F117`。

## Emoji 深评

改前／初次功能构建的一次热采样中，纯文本排版分配分别为 1,398,640／1,401,440 B，60 emoji 为 1,871,456／2,787,432 B，耗时为 18.30／34.39 ms；旧版与新版可见图片分别是 0／60。新增显示功能的成本与潜在实现开销混合，不以旧版无图像的分配量认定都是退化。首次在已排好纯文本的窗口里添加一个 emoji，功能构建该次排版为 95.81 ms，进程私有内存上升 22,458,368 B；该差值不能全部归因于单个图集，且单次冷启动受系统缓存影响。

反事实只改变 `EmojiSprite.Create`：以并发字典复用冻结的 `CroppedBitmap`，保留所有图片及其尺寸；补丁 `cache-control.patch.txt`。按现状／缓存／缓存／现状交错四批，60 个 emoji 热排版分配分别为 2,787,432／2,750,472／2,750,472／2,787,432 B，配对耗时 31.56／32.62／32.96／32.43 ms，可见图片均 60。复用稳定减少 36,960 B，但仅覆盖相对旧版约 0.92 MB 差额的一小部分，未观察到时间改善；没有调用栈或保留同外观的其他实现，不能把剩余差额全部归因于控件布局或称其不可避免。未测 Twemoji 首次加载、完整原生/GPU 内存及真实超长对话。
