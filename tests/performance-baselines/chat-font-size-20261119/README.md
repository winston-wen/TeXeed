# AI 阅读字号和字重性能（2026-11-19）

Windows 10.0.26300、WindowsDesktop 10.0.7。同一主机在屏幕外启动不激活的 WPF 窗口，每版使用隔离项目和配置。每项两次预热、七对样本。首次反馈计至 ApplicationIdle。随后等待 800 ms、草稿保存计时器与保存锁，与等长空操作配对校正耗时和 UI 线程分配。负校正值反映调度波动。可见控件按与窗口相交估算，未完全扣除祖先裁剪。测试不依赖网络或物理键鼠。

## 120 轮常态会话

沿用 [120 轮性能夹具](../manual-form-unlock-20261118/panel-fixture.cs.txt)，在 900×760 与 620×760 DIP 间交替变宽。历史各列取同一主机和运行时重测的两个历史构建的较小值。完整条件、各项历史构建和明细见 [同环境历史基准](../chat-viewport-20261119/README.md)。旧版缺少后来新增的功能。

| 操作 | 历史／0.5.15／0.5.16 候选分配 | 首次反馈 | 校正耗时 | 可见控件 |
| --- | --- | --- | --- | --- |
| 草稿输入 | 255,256／262,048／262,048 B | 2.93／3.58／3.91 ms | 2.12／0.87／5.10 ms | 40／47／47 |
| 变宽 | 558,104／867,704／867,704 B | 16.32／15.52／17.71 ms | 13.84／15.85／20.30 ms | 40／47／47 |
| 滚动 | 177,024／189,504／189,504 B | 0.88／1.55／1.09 ms | 1.50／−2.26／1.37 ms | 40／47／47 |
| 编辑框变高 | 109,280／116,048／116,048 B | 2.86／3.33／3.57 ms | 1.65／2.04／0.12 ms | 40／47／47 |

四项分配中位数与改前一致，滚动时三个样本少约 7 KB。变宽距同环境历史最佳仍差 309,600 B，已知虚拟化缓存有布局成本，已有数据尚不能把历史差额完整拆为功能及可避免开销。候选已包含三位轮次号所需的 11 DIP 轮次内留白。同批短时执行了原生回归，耗时仅反映该批观察值。原始逐次记录见 `before-panel.json`、`after-panel.json`。

## 长回答标题

[标题夹具](fixture.cs.txt) 用一轮包含 24 个六级标题及 24 段中英混排的合成回答，调用实际的标题点击路径折叠及展开第一个一级标题，再交替改变窗口宽度。测量外层虚拟布局与阅读区排版。该夹具首轮基准为 0.5.15。旧有标题性能记录的文本、操作或测量方法不同。标题夹具采样使用加入三位轮次号有条件留白前的候选构建，单轮夹具使用一位轮次号。

| 操作 | 改前／候选分配 | 首次反馈 | 校正耗时 | 可见控件 |
| --- | --- | --- | --- | --- |
| 折叠后展开 | 8,189,896／6,962,192 B | 72.43／59.75 ms | 63.15／60.19 ms | 27／27 |
| 窗口宽度交替变化 | 9,095,296／10,166,224 B | 82.12／112.44 ms | 86.30／109.92 ms | 27／27 |

900 DIP 宽时，展开回答由 3,470 增至 3,845.2 DIP。在 620 DIP 宽时由 4,670 增至 5,870.32 DIP。交替变宽共七次，四次从 900 缩到 620 DIP。每次缩窄约多 1.07 MB，每次从 620 扩到 900 约少 1.23 MB。折叠后展开也少约 1.23 MB。逐次数据见 `before-dense.json`、`after-dense.json`。

在同一候选程序集把合成长回答从 18 调回 16 DIP，保留 600 字重及新版实现，回答高度恢复到改前水平，缩窄分配恢复到 9,097,696 B，距离旧版 9,095,296 B 仅 2,400 B。约 1.069 MB 的增量与字号和折行相关。此对照未逐项采集 WPF 内部调用栈，无法区分额外折行成本与其中可避免的布局开销。折叠后展开的分配为 8,204,240 B，和旧版相差约 14 KB。单批反馈耗时有波动。对照只用于分析，样本见 `size16-dense.json`。

## 复测

使用 [WPF 测量宿主](../annotation-modes-20261118/Harness.csproj) 以 Release 编译。将 `ProductDir` 指向对应产品的完整目录，`Fixture` 指向需要的夹具绝对路径。将同一份 `TeXeed.AppTests*` 宿主放入两版各自完整产品目录的独立副本，核对程序集和夹具指纹，再依次执行 `dotnet TeXeed.AppTests.dll <隔离输出目录>`。使用标题夹具时，参数 2 可指定测试用正文字号，在候选程序上只调整合成长回答的字号以对照折行和排版开销。

原型的历史、改前及改后数据见 [浏览器原型性能](browser.md)。
