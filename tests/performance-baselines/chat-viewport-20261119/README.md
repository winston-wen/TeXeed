# AI 会话视口性能（2026-11-19）

在同一台 Windows 10.0.26300、WindowsDesktop 10.0.7 主机采样。两个夹具都使用 Release 构建、900×760 DIP 屏幕外窗口、独立项目和配置，窗口不激活。每项两次预热、七对样本。首次反馈计至 ApplicationIdle，随后等待 800 ms、草稿保存计时器与保存锁，和相邻空操作配对校正时间及 UI 线程分配。可见控件按与窗口相交估算，未完全扣除祖先裁剪。计时单批且调度波动，负的校正值不能用于耗时排序。

## 120 轮常态会话

沿用 [120 轮性能夹具](../manual-form-unlock-20261118/panel-fixture.cs.txt)，逐项测量草稿输入、变宽、滚动和输入框高度。用该夹具在本次环境复测两个保存过历史最佳的确切程序集（0.3.47 与引用界面构建），再测正式 0.5.14 和 0.5.15 候选。历史构建缺少后来新增的功能。原先历史最小分配为 253,864／550,296／176,328／108,584 B，源样本为 [0.3.47](../ai-docked-composer-20261110/history-verified.json) 和 [引用界面构建](../context-branch-ui-20261110/native-after.json)。本次在同机、同运行时、同窗口条件下重测这两个程序集的最小值为 255,256／558,104／177,024／109,280 B，完整样本见 `history-0347-panel.json` 和 `history-context-panel.json`。

## 原型返回来源

同一 Windows 主机使用 Chrome 157.0.8103.79、1000×820 视口和 [原型来源返回夹具](../inline-return-20261112/measure.cjs)，120 轮、60 分支及一处折叠章节。比较历史 `cf7cb23`、改前 `a83f243`、改后原型各一批，每项两次预热及七对样本，等待两帧和 220 ms。V8 以 1,024 B 间隔采样，报告净采样分配的中位数。

## 复测

使用 [WPF 测量宿主](../annotation-modes-20261118/Harness.csproj) 编译，`ProductDir` 指向对应程序集所在的完整应用目录，`Fixture` 指向上文夹具的绝对路径。将生成的 `TeXeed.AppTests*` 文件复制到该版本应用目录的独立副本，核对程序集 SHA-256，再运行 `dotnet TeXeed.AppTests.dll <独立输出目录>`。同一夹具可为不同应用程序集版本分别编译，也可在 .NET 允许的版本范围内使用同一宿主。测试应串行并避免与其他构建或桌面测试重叠。

原型复测使用 `TEXEED_PLAYWRIGHT_PATH` 和 `TEXEED_BROWSER_PATH`。将 `inline-return-20261112/measure.cjs` 复制到仓库根目录下深度为三的隔离输出目录，例如 `artifacts/chat-viewport-perf-20261119/prototype`，把 `archive('dddee8f')` 换成 `archive('a83f243')`，去掉操作数组中的 `'toggle'` 条目，执行 `node <夹具路径> <输出 JSON 路径>`。
