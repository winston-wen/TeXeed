# 行内追问链接与上游回源性能（2026-11-12）

同一 Windows x64 主机、.NET SDK 10.0.203、900×760 DIP WPF 窗口，使用隔离 `TEXEED_HOME` 和合成文档，桌面测试串行。各版本独立进程，每项预热两次、采样七次，用相邻 ApplicationIdle 空操作校正耗时及 UI 线程托管分配；控件数按窗口内相交的可见 Control 计算。后台线程分配、GPU、真实输入法与服务器请求未计入。修改前为 commit `dddee8f` 的 0.4.12 发布程序集，修改后为本次功能构建；程序集、夹具和产品源码哈希见 `manifest.json`。正式发布后重建的程序集未测。

## 追问插入与折叠

`folding-fixture.cs.txt` 原样沿用 `../graph-canvas-20261111/` 的 60 段、每段约 180 字夹具，父会话不切换，连续从同一选区创建追问并保存，每批中位数处已有约六条链接。两版各两批，以旧→新、新→旧的顺序运行。

| 操作 | 历史同功能可复核样本 | 修改前两批 | 修改后两批 |
| --- | --- | --- | --- |
| 新建追问 | 2,680,912 B／44.39 ms／33 控件 | 2,682,200 B／40.25–41.46 ms／36 控件 | 2,712,072–2,712,432 B／38.65–42.32 ms／36 控件 |
| 折叠再展开 | 5,122,920 B／85.02 ms／36 控件 | 5,124,968 B／73.15–80.31 ms／39 控件 | 5,024,760 B／73.22–74.57 ms／39 控件 |

历史样本已经具备即时来源链接，但使用独立块；新链接放在选区末尾的行内。更早 0.4.5 的 160,448 B 未即时插入链接，只能作缺少功能的参照。新建追问相对修改前稳定多约 29.9–30.2 KB；耗时区间重叠，不据此判断速度变化。

`reason-fixture.cs.txt` 沿用历史反事实夹具，按无链接／正常／正常／无链接交错两批：不插入链接为 161,176 B／14.47–15.16 ms／30 控件，正常为 2,712,432 B／38.27–39.18 ms／36 控件。这个反事实缺少即时来源链接，约 2.55 MB 差额包含链接、定位和 WPF 排版，不能认定全部不可避免。另将行内链接使用的新缓存解析器替换为旧的仅可见文本解析器，按反事实／正常／正常／反事实交错两批，分别为 2,833,152–2,833,512 B 与 2,712,432 B、均为 36 控件；旧解析器不能可靠处理折叠的旧锚点，因此并非可用替代。未采分配调用栈，约 30 KB 相对改前的增量仍混合行内功能成本及可能的实现开销，尚未完全拆分。

## 折叠内容回源

`navigation-fixture.cs.txt` 使用同样 60 段资料，分成前兄弟、目标章节和后兄弟；每次测量前折叠三者，再返回目标。两版各两批，旧→新、新→旧交错。旧版热跳转为 5,008,848 B／68.17–74.59 ms／30 控件，新版为 1,725,672 B／24.11–26.35 ms／30 控件；旧版展开兄弟且来源在距顶 24 DIP，新版保留兄弟折叠、来源在 282.1／564.2 DIP 视口中线。功能不同、布局工作量不同，不能把差额解释为同功能实现的提速。此场景没有满足新功能的历史最佳。JSON 中 `cold-navigation` 是创建追问后的首次跳转，行内链接插入可能已预热来源文本缓存，不代表空缓存冷启动。

## 复测

历史和相邻版本数据分别保存在 `../graph-canvas-20261111/` 与本目录的 `folding-*.json`、`navigation-*.json`。`resolver-*.json` 和 `link-*.json` 为上述两组反事实及配对样本。将每份 `*.cs.txt` 复制为独立目录中的 `Program.cs`，将 `Runner.csproj.txt` 复制为 `Runner.csproj`，以 `dotnet build Runner.csproj -c Release -r win-x64 -p:TeXeedAssemblyDir=<0.4.12 发布目录绝对路径>` 编译。将构建结果和 0.4.12 发布目录的依赖 DLL 复制到独立运行目录；新版运行目录再用最终源码 Release 构建的 `TeXeed.dll`、`TeXeed.Core.dll` 覆盖。运行 `dotnet Runner.dll <全新的独立输出目录>`。反事实 `reason-fixture.cs.txt` 的第二个参数 `suppress` 会阻止即时插入链接；解析器反事实仅将 `MarkdownView.BranchLinks.cs` 中 `ResolveBranchAnchor(anchor, before, after, reveal: false)` 换为 `ResolveUserBookmark(new AiUserBookmark { Anchor = anchor, ContextBefore = before, ContextAfter = after })` 后隔离编译。按本文顺序串行运行，避免同时运行其他桌面测试。
