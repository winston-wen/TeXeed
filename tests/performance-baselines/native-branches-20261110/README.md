## 关系图深评和优化

使用 `fixture-deep.cs.txt`，相同程序、窗口和主题；模拟 0、15、60、120 个子会话，以正向再反向顺序运行两遍，每次预热两次、采七次，测打开时与相邻空 ApplicationIdle 配对的耗时及 UI 线程分配。窗口内实际可见控件数分别为 3、19、25、25，未包含 GPU 内存。各批原始数据在 `deep/`；名称 `deep` 为全部 TreeViewItem 预创建版本，`virtual` 为全部数据绑定虚拟化版本，`hybrid` 为小树直接创建、大于 24 项使用虚拟化的最终功能构建。各批是按版本顺序而非版本交错，耗时受机器负载影响。

| 子会话数 | 原实现分配／耗时 | 虚拟化分配／耗时 | 最终实现分配／耗时 |
| --- | --- | --- | --- |
| 0 | 200.4 KB／17–22 ms | 260.0 KB／18 ms | 200.4 KB／19–31 ms |
| 15 | 1.137 MB／34 ms | 1.658 MB／39 ms | 1.137 MB／35–36 ms |
| 60 | 3.972 MB／76 ms | 3.395 MB／65–66 ms | 3.395 MB／65–66 ms |
| 120 | 7.651–7.656 MB／138–145 ms | 3.425 MB／65–66 ms | 3.425 MB／65–66 ms |

原实现通过递归创建所有 `TreeViewItem`，60 与 120 项可见控件相同但分配和耗时随数量显著增长；虚拟化只生成所需容器，120 项显著下降，仍有模型构造与可见项排版成本。纯虚拟化在 15 项多分配约 521 KB，故保留小树的直接创建路径；此阈值是当前夹具下的实现选择，不意味着不同主题、层级与数据下一定最优。两路径均通过多级节点及双击回归，尚未测更多分支、真实鼠标连续操作与长标题。未测量树中展开已折叠节点、输入法、真实 AI，以及官方版本号改后重新构建的程序集；整体性能不能仅凭此组结论宣布完全通过。

## 变宽分配增量的工具栏对照

使用相同功能构建 DLL `684444E771E34BE7254141C49D239D6B6430B1A00D3F4C726DE060E75519E824`，同一 120 轮夹具、相同窗口与等待方法，仅执行变宽，保留原本空编辑框（与上表先输入后变宽的条件不同）。构建三种反事实：不初始化工具栏；初始化工具栏但清空其子控件并保留实际相同行高；正常工具栏。关闭／开启／开启／关闭和占位／开启／开启／占位分别交错各两批，每批预热两次采七次。

| 条件 | 变宽分配中位数 | 可见控件 |
| --- | ---: | ---: |
| 无工具栏 | 两批均 503,088 B | 41 |
| 等高空占位 | 两批均 503,224 B | 41 |
| 正常工具栏 | 四批均 508,488 B | 42 |

在此夹具中，保留行高而改变阅读区几何的差额为 136 B；正常工具栏相对等高占位多 5,264 B，说明主要增量来自新增工具栏内容及其 WPF 排版，而不是阅读区高度变化。正常工具栏相对完全关闭多 5,400 B，与上表相对旧版的 5,496 B 量级接近；因为编辑框状态和程序版本不同，不能把这两组数字机械相减。正常工具栏是在用户要求收纳会话关系等入口后新增的功能；5,264 B 包含实际入口按钮与其布局，但当前未采调用栈，也未验证保持相同行为及外观的替代实现，不能称它全部是不可避免的功能成本。校正耗时随调度波动，两种反事实两批各约 15–18 ms，不据此判断快慢。此对照未覆盖追问子会话时额外显示的返回按钮。`resize-detail/` 保存八批原始样本和夹具，桌面及运行条件同前述功能构建。
