# 行内公式基线与纯数字性能（2026-11-19）

Windows 10.0.26300、WindowsDesktop 10.0.7。两版均使用 Release 构建，独立 WPF 窗口位于屏幕外、保持未激活。每项两次预热、七对样本。首次反馈计至 ApplicationIdle；配对校正纳入后续 800 ms 空闲、布局，以及适用的公式任务、草稿保存计时器和保存锁。列出的耗时和 UI 线程分配为样本中位数，可见控件按与窗口相交估算。负的校正时间表示该项与配对空操作间的调度波动。

## 测量场景

- [混排长回答](../ai-reading-axis-20261119/fixture.cs.txt) 含 30 段、五个标题。每段有行内 `$0$`、`$1$` 和 `$D$`，末尾还有一条行间公式。全文重排后等待 SVG 热缓存及排版完成，窗口交替变宽和替换追问时保留四个气泡。对原夹具应用 [显示结果检查补丁](mixed-fixture.patch)，只在计时结束后读取正文和公式控件。旧版应有 91 个公式控件，新版应有 31 个，并能在原生文档文本中连续读出 30 处“输出 0 或 1”。
- [常态会话](../manual-form-unlock-20261118/panel-fixture.cs.txt) 含 120 轮，测主草稿输入、窗口宽度交替、跨轮滚动及主编辑框增高。
- [标题密集回答](../chat-font-size-20261119/fixture.cs.txt) 含 24 个标题和 24 段混排正文，测折叠展开、窗口变宽和变窄。

混排 21 个样本都测到原来的 91 个公式变为 31 个，并实际读出全部 60 个纯数字。混排重排、变宽和替换气泡的分配中位分别少 1,307,960、895,648 和 7,264 B。前两项也低于同机历史样本。三个操作的首次反馈都有所缩短。变宽的排队校正中位升高 5.36 ms，两组分布重叠。计入 800 ms 等待的原始耗时中位由 839.76 变为 841.24 ms，配对空操作中位由 811.66 变为 805.12 ms。分配的改善包含纯数字改用文字和行内公式省去墨迹中轴测量，两者各自的份额未单独测量。[改前混排](before-mixed.json) · [改后混排](after-mixed.json)

## 复测

使用 [WPF 测量宿主](../annotation-modes-20261118/Harness.csproj)。混排测量先将原夹具复制到空目录，在含有 `fixture.cs.txt` 的目录用 `git apply --no-index` 应用补丁。将 `ProductDir` 指向对应完整应用目录，`Fixture` 指向相应夹具的绝对路径，用 Release 编译。将宿主生成的 `TeXeed.AppTests*` 文件复制进各独立应用副本，再运行 `dotnet TeXeed.AppTests.dll <隔离输出目录>`。混排夹具的第二个参数是 [SVG 样本目录](../quote-scroll-20261116/math-svg/) 的绝对路径；0.5.20 另传第三个参数 `decimal-text`，按普通文字验证纯数字。此夹具测量从缓存读取和混排，不计 TeX 引擎冷启动。

浏览器原型的基线测量、数字密集样本及实际构建检查见[浏览器结果](browser.md)。
