# 圈点、批注与预览入口性能（2026-11-18）

同一 Windows 主机、.NET WindowsDesktop 10.0.7、Ristretto、屏幕外且不激活的 WPF 窗口，隔离 `TEXEED_HOME` 与项目数据，各项预热两次、七对样本。普通会话夹具 900×760 DIP，配对 800 ms 草稿保存及保存锁；专项 1200×800 DIP，配对 250 ms 和 ApplicationIdle。历史可复核普通会话最佳见 `../steering-20261112/`，但历史窗口可见且运行环境不完全一致，不能直接当成本轮同环境成绩。0.5.8 正式发布程序集的原始样本为 `before-normal.json` 和 `before-modes.json`，实际程序集、PDFium、夹具与宿主指纹见 `before-fingerprints.json`。

`../queue-handoff-20261117/panel-offscreen.cs.txt` 创建 120 轮会话和长过程记录，分别测输入、变宽、滚动和编辑框高度。采样时曾复制到本目录，二者 SHA-256 相同，现使用原有已提交的夹具复测。`modes-fixture.cs.txt` 用合成项目、120 行源码和一页 PDF，分别测源码选区、源码和 PDF 模式开关、源码和 PDF 菜单 `Opened` 事件及设置窗口显示。菜单只触发打开事件，不打开真实弹出菜单；设置窗口屏幕外显示后关闭，控件数包含该窗口。选区通过程序设置，不使用真实鼠标；PDF 栅格及截图后台线程、GPU、实际编译和网络不计入 UI 线程分配。

旧版菜单打开事件会查询系统剪贴板；本机这批源码菜单事件中位耗时约 1.07 秒，不能仅据此归因代码，也不能代表真实交互表现。首次启动专项因 PDFium 原生库未复制而失败，没有有效样本；后续复制正式发布目录的 `pdfium.dll` 再采样。

普通会话旧版输入／变宽／滚动／编辑框高度的配对分配中位分别为 262,032／853,544／190,144／116,048 B，均 47 个可见控件；配对耗时 2.92／15.92／1.29／2.18 ms。历史可复核最佳分别为 253,864／550,296／176,328／108,584 B，历史版缺少后续功能且条件不同。专项中位数为源码选区 458,704 B、源码模式切换 3,680 B、PDF 模式切换 21,288 B、设置窗口显示 1,600,848 B；菜单仅采事件而不渲染弹窗，控件数分别见原始样本。

复测时以 `Harness.csproj` 的 `ProductDir` 指向对应版本的完整发布目录、`Fixture` 设为待运行的 `.cs.txt` 文件，构建隔离 WinExe 宿主，并将同版 `pdfium.dll` 复制到宿主目录。依次传入新的独立输出目录运行，串行采样，不与构建、浏览器测试及其他性能测量重叠。`new-features-fixture.cs.txt` 测新版实际从源码选区建批注、PDF 区域截取并建批注以及关闭／重新打开主预览；旧版不提供相同行为，没有同功能历史最佳。

`final-normal.json` 和 `final-modes.json` 是最后功能构建的各一批，`final-new-features.json` 是新增操作，指纹见 `final-fingerprints.json`；`intermediate-*` 为源码切换修复前的中间版本，不能当作最终数据。首次新增操作夹具没有等待异步浮窗，失败且没有有效样本；最终夹具等待浮窗实际打开。

最终普通会话输入／变宽／滚动／编辑框高度的配对分配分别为 262,112／853,624／190,184／116,128 B，控件均 47；对照分别 262,032／853,544／190,144／116,048 B。各一批，小额差异不足以判断稳定性。功能构建而非发布程序集。最终新增源码选区批注／PDF 区域截图批注／关闭主预览的配对中位为 108.06／122.37／16.59 ms，分配 492,024／504,872／3,377,856 B，控件 57／57／41；无旧版同功能基准，分配包含新功能成本和可能的可避免开销。

设置专项首批在工作区上下文测得旧／新 32.27／139.77 ms、1,600,848／1,907,800 B、76／84 控件。`settings-deep.cs.txt` 在独立屏幕外窗口按旧→新→新→旧交错各采一批，七对结果为 `settings-before1/2.json`、`settings-after1/2.json`：构造中位旧版 4.94／5.33 ms、新版 5.66／5.62 ms；`Show` 中位旧 28.35／29.70 ms、新 31.98／34.18 ms；校正后旧 35.08／38.36 ms、新 37.67／50.21 ms。独立窗口构造／显示后的控件数为 30／38，配对 UI 分配旧约 1.57 MB、新约 1.87 MB。按工作区完整夹具重测得到 `before-modes-2.json` 与 `final-modes.json`，旧／新为 137.89／138.82 ms、1,596,248／1,909,712 B、76／84 控件；因此约 140 ms 的情况在旧版也可复现，首批差异不能直接归因本次修改。独立及工作区两种夹具均显示约 0.30 MB 的分配增加；分段样本显示主要增量发生在窗口显示阶段，包含新设置控件与布局，也可能含可避免的实现开销，尚无同功能反事实或调用栈，不能完整归因。性能简评触发后已做交错深评，但设置分配差额未完全解释，不宣称完整验收通过。
