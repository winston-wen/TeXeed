# 长答题原型性能

同一 Windows 主机使用相同 Chrome、48 轮合成会话，在中段放置一个长答题框。对照首个支持答题的原型 `fb4ff2a`、改前 `4dd276b` 和本次改后。1000 × 1000 像素输入 12 个逻辑行，390 × 1000 像素输入不含换行符的中英混排长句，然后缩回一行文本。每种宽度七个有效样本，预热两次。三个批次交错使用版本顺序。读取控件实际高度和位置记录同步反馈，等待两个动画帧后扣除配对空操作。可见控件按阅读区边界统计，V8 堆采样为 JS 分配估算，包含预热、两项操作和采样开销。

测量在浏览器原型上采集。原生长答题框另用 WPF 夹具测量。测试使用脚本赋值和输入事件做计时，另有浏览器真实键盘、滚轮、删除、调整窗口及重开草稿的功能回归。

| 原型操作 | 历史／改前／改后同步反馈中位数 | 两帧校正耗时 | 可见控件 |
| --- | --- | --- | --- |
| 宽窗口加行 | 0.8／0.9／0.9 ms | 0.0／−0.1／0.2 ms | 7／7／7 |
| 宽窗口减行 | 0.7／0.8／0.6 ms | 0.1／0.0／0.0 ms | 7／7／7 |
| 窄窗口折行 | 0.9／0.8／0.6 ms | 0.1／−0.1／0.0 ms | 6／6／7 |
| 窄窗口减行 | 0.6／0.7／0.6 ms | 0.0／−0.1／0.0 ms | 6／6／7 |

同期复测历史版本和改前版本，以各项同夹具较小值作为比较基准。宽窗口的 JS 采样中位为历史 311,460 B、改前 314,628 B、改后 290,608 B。窄窗口分别为 283,636 B、291,584 B、360,468 B。行号节点复用和避免重复排版回调降低宽窗口的采样值。窄窗口新增可用的局部滚动范围，高度上限多留出一个可见控件。三次采样仍比改前高约 29–75 KB，V8 批次估算尚不能将差额分配给局部滚动、控件可见范围或其余浏览器工作。此结果不作为已消除窄窗口分配增量的依据。

改后在放入长答案时均为 200 像素，即八行正文及边框、内边距。删除减至 80 像素，即三行。原型夹具中三个版本的字段屏幕位置均未变化。原始记录见 `browser-results.json`。

## 复测

在仓库根目录运行 `node tests/performance-baselines/multiline-form-20261119/browser-measure.cjs`。需要 Playwright 或设置 `TEXEED_PLAYWRIGHT_PATH`，可用 `TEXEED_BROWSER_PATH` 指定 Chrome。结果保存至 `artifacts/prototype-multiline-20261119/benchmark/results.json`，包括浏览器版本、资源指纹和每次测量。
