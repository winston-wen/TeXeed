# 长答框原生性能（2026-11-19）

Windows 10.0.26300、WindowsDesktop 10.0.7。同一主机以 Release 程序集和不激活的屏幕外 WPF 窗口采样。各版使用独立工作区和设置，每项两次预热、七对样本。首次反馈计至 ApplicationIdle。随后连同 800 ms 空闲、草稿计时器、保存锁配对校正耗时与 UI 线程分配。可见控件按与窗口相交估算，未完全扣除祖先裁剪。单批时序受调度影响，负校正值反映波动。

## 120 轮常态会话

沿用 [常态夹具](../manual-form-unlock-20261118/panel-fixture.cs.txt)，宽度在 900 与 620 DIP 间交替，窗口高度为 760 DIP。历史列取同一主机及运行时重测的两个历史构建各项较小值。旧版与现行版功能不同。逐次数据和重测条件见 [同环境历史基准](../chat-viewport-20261119/README.md)。

| 操作 | 历史／0.5.16／0.5.17 候选分配 | 首次反馈 | 校正耗时 | 可见控件 |
| --- | --- | --- | --- | --- |
| 草稿输入 | 255,256／261,416／262,128 B | 2.93／2.99／3.55 ms | 2.12／−1.46／4.27 ms | 40／47／47 |
| 变宽 | 558,104／867,704／867,784 B | 16.32／16.21／16.69 ms | 13.84／12.50／18.09 ms | 40／47／47 |

四项可见控件中位数与改前一致，分配中位分别高 712／80／40／80 B。中间构建与最终候选四项分配中位相同，既有历史差距仍集中于缩放窗口。草稿输入的 712 B 差额在这两批候选的七对样本均出现。普通夹具没有长答字段，无法据此归于字段显隐成本。批次部分重叠，样本未包含分配调用栈，细分开销尚未定位。见 `before-panel.json`、`after-panel.json`、`anchor-panel.json`。

## 长回答内编辑与滚动

[长答框夹具](fixture.cs.txt) 使用 120 轮会话，第 61 轮的长答框之前有 25 段正文，之后有 38 段。每次先把字段和前文定位在 900×760 DIP 窗口内，再通过 WPF 文本框追加或删除文字，或发送滚轮路由事件。折行场景在固定宽度下追加不含换行符的文本。保存路径与产品一致，字段未取得焦点。样本记录字段及前文的实际屏幕位置、实际视觉行数、内外滚动偏移和控件数。带焦点的换行、退格、选区、光标导航及自动折行后滚动条由应用专项回归覆盖。本场景以正式 0.5.16 为最早可复测比较点。0.5.16 样本的标签沿用初稿，实际宽度前后均为 900 DIP。最终候选是提交前通过长答框交互验收的 Release 构建。

| 操作 | 0.5.16／0.5.17 候选分配 | 首次反馈 | 校正耗时 | 可见控件 |
| --- | --- | --- | --- | --- |
| 六行增至十二行 | 856,360／841,744 B | 16.43／16.67 ms | 11.44／16.74 ms | 47／50 |
| 十二行减至六行 | 691,592／768,104 B | 11.41／12.58 ms | 14.85／13.65 ms | 47／47 |
| 一个逻辑行折成九个视觉行 | 646,352／747,600 B | 25.21／42.37 ms | 30.61／45.49 ms | 47／50 |
| 长答框内滚轮 | 355,600／223,752 B | 8.27／5.60 ms | 4.07／2.37 ms | 47／51 |

候选的十二个显式行及九个折行都封顶在 202 DIP（八行及文字内边距），改前分别为 302／227 DIP。两版的非聚焦文本替换都保持字段与前文位置。滚轮每次推进 48 DIP，旧版移动会话，候选只移动字段。滚动前后视口内容不同，分配差额随行为变化。逐次记录见 `before-field.json`、`after-field.json`，中间构建样本见 `anchor-field.json`。

在同一中间构建里仅将该字段的纵向滚动条设为 Disabled，八行高度和会话锚定仍生效。减至六行和单行折成九行的分配从 768,064／747,560 B 回到 693,008／645,016 B，接近 0.5.16 的 691,592／646,352 B。另一组保持滚动条并仅卸掉字段的会话锚定处理，分配为 767,536／746,648 B，分别少 528／912 B。增量主要随 WPF 自动滚动条显隐和重排出现。本次记录未采集 WPF 内部调用栈，细分开销尚未定位。测量批次部分重叠，计时只记录当批观察值。逐次记录见 `disabled-bar-field.json`、`disabled-anchor-field.json`。

## 复测

使用 [WPF 测量宿主](../annotation-modes-20261118/Harness.csproj) 以 Release 编译。将 `ProductDir` 指向对应版本的完整应用目录，`Fixture` 指向需要的夹具绝对路径。将测量宿主的 `TeXeed.AppTests*` 文件复制到各版本应用的独立副本，核对程序集和夹具指纹，再依次执行 `dotnet TeXeed.AppTests.dll <隔离输出目录>`。长答框夹具的第 2 参数可选 `disable-bar` 或 `disable-anchor`，用于对应的候选内对照。

原型数据见 [浏览器性能](browser.md)。
