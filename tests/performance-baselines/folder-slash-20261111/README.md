在同一 Windows 主机、.NET 10、900×760 DIP WPF 窗口测量。修改前使用正式 0.4.8（TeXeed.dll SHA-256 `FAA52CAE3D40CD243A8FAEA3D22B4090B911D191547FB2B8C6FDDAE951BA2CB3`）；最终功能构建为 `67FDDFF7AFC8E6F70BD4E79AC22C978BCB691E9A57A8ABB16A6C5DAE545F6A43`，测量后只调整了版本号，重新发布的二进制未测。`final-panel.cs.txt`、`final-model.cs.txt` 和 `final-panel.xaml.txt` 留存相关功能源码，夹具及样本不含真实用户文件。

## 普通会话

`panel-fixture.cs.txt` 沿用 120 轮、每轮 3 条 200 行过程记录，每次预热 2 次并采 7 次，按相邻空队列、800 ms 保存等待与锁配对校正。旧／新各一批，输入 259,040／259,040 B、变宽 561,792／561,792 B、滚动 180,224／181,040 B、编辑框高度 108,584／108,584 B，可见控件 45／45。对应配对中位耗时分别为 2.54／2.91、12.79／14.30、6.51／0.50、3.80／1.83 ms；800 ms 等待的调度波动大，不根据数毫秒差异判断快慢。同夹具可复核历史最佳分配分别为 253,864、550,296、176,328、108,584 B；历史版缺少后续书签和导航等功能，不能将差额全部当作退化。

滚动单项用 `scroll-fixture.cs.txt` 固定为同一输入与 620 DIP 窗口后交错旧、新、新、旧两批。旧版中位均 180,320 B，新版 184,904／199,432 B；新版本逐次包含 180,320 B 与 1–2.3 MB 的虚拟化峰值，部分相邻等待的扣除还出现异常，原先观察到的 816 B 没有稳定复现。该夹具没有打开附件弹窗，且产品滚动路径没有直接修改，但现有样本不足以判定差异是异步排版／调度还是退化；不宣称性能完全通过。样本为 `panel-before.json`、`panel-after.json`、`sb1/sa1/sa2/sb2.json`。

## 原型

`prototype-folder.cjs` 在 Chrome 157、1000×820、120 轮、一条引用和一个含 31 文件的长目录下，旧工作树 HEAD（0.4.8）与修改后各测一批。附件弹窗打开同步中位 3.9／4.4 ms、CDP V8 采样 19.7／18.6 KB；DOM 1,193／1,196，估算可见控件 15／15。配对采样可能为负且只一批，不判断小额分配变化。旧版没有同路径的新省略功能，历史短目录候选在 `attachments-separated-20261111/prototype-folder.json`，不能作严格排名。资源哈希与逐项样本见 `prototype-folder.json`。

## 复测

以 `list-fixture.cs.txt`、`panel-fixture.cs.txt`、`scroll-fixture.cs.txt` 分别编译 .NET 10 Windows WPF WinExe，引用相应版本 TeXeed 和 TeXeed.Core 及依赖，使用独立 `TEXEED_HOME`，同机桌面串行运行。命令行第一个参数为各自独立输出目录，列表夹具第二个参数为 `short` 或 `long`。目录夹具 SHA-256 `03E46490E425176E60E13943BC60FE8912FFA1C1DD151BE726B41208C680B376`，普通会话夹具 `A52DB958492CAF50D84BAC50BEE5131F98CEEDF093C490392A8C56D91099C95D`，滚动夹具 `F1AA23C8A1503F0CDC1CD8E028220536BF9EF79AD2321EC8303572ACC62640D9`。原型夹具在仓库根设置 `TEXEED_PLAYWRIGHT_PATH` 和 `TEXEED_BROWSER_PATH` 后运行，使用 git HEAD 归档的 0.4.8 与工作树原型；以后需将脚本的 HEAD 固定为 0.4.8 commit。真实系统剪贴板、输入法、不同物理 DPI 和正式发布二进制未测。
