# 公式引用预览与跳转（2026-11-23）

## 原生阅读区

在同一台 Windows 10.0.26300、.NET Desktop 10.0.7 主机上，使用 900 × 680 DIP 的 WPF 窗口，装入实际的 MarkdownView 与 ChatScrollViewer。回答含 30 段、7 个标题、90 个行内公式、30 个指向同一标签的引用。两组源文分别引用单行公式或带两行对齐等式的公式，均实际经过 TeX 生成 SVG。预热排版、字体及 SVG 缓存后，单独测量全文重排、处于文末的最后一个引用单击、从同一阅读位置打开目标。每组两次预热、七次采样。

单击在渲染所得的 Hyperlink 上触发 WPF Click，0.5.20/0.5.21 均直接滚到公式。0.5.22 的单击打开原生 Popup，双击测试依次触发同一链接的 Click 与第二次按下事件（ClickCount=2）。旧版打开目标只需一次点击。下表将不同版本打开目标所需的完整操作计入导航时间。真实鼠标事件由原生交互回归另测。

每个样本都测至首次 WPF ApplicationIdle，另记录等待 620 ms 并再次排空 Dispatcher 后的总时间和 UI 线程分配，扣除相邻空操作。波动可使校正时间短暂为负。可见控件分别统计主窗口与打开的浮窗中，实际布局与窗口相交的 WPF Control。浮窗未打开时也核验其销毁状态。采样完成后核对真实 SVG 的原式、外层滚动位移与目标的视口坐标。数据可从[逐次原生样本](native-samples.jsonl)复核。

## 复测

用[现有 WPF 宿主](../annotation-modes-20261118/Harness.csproj)编译[本场景夹具](fixture.cs.txt)，传入 `-p:Fixture=<夹具绝对路径>` 和 `-p:ProductDir=<0.5.21 发布目录>`。为各产品版本建立完整发布目录的副本，将同一套 `TeXeed.AppTests*` 宿主文件复制进去。在 Windows 上运行 `dotnet <副本>/TeXeed.AppTests.dll <独立结果目录> one-line`，两行目标用 `two-line`。0.5.22 追加 `preview` 来核验单击与双击的实际结果。追加 `diagnose` 时，在相同窗口测量读取引用的字形矩形、目标缺失的提示窗和同位置公式预览。测量时在独立桌面启动窗口，保留本机显示和 DPI 设置。需要安装可用的 LaTeX 及 dvisvgm。
