# 会话关系与主 PDF 预览的标签切换

Tectonic 编译八页、320 行的单主文件项目。原生主窗口通过 AI 面板的「会话关系」按钮打开图，关闭对话标签，保持关系图在右栏活动并正常关闭窗口。每轮用一个新的主窗口打开同一项目，依次切到 PDF、切回关系图、关闭图回到 PDF，再重新打开关系图。关系图含一个根会话和 60 个有回答的子会话。窗口大小为 1200 × 760 DIP，未激活，使用独立项目、配置与真实 PDF 缓存。关闭实时编译和源码跟随。

0.5.19、0.5.20 各七次恢复都在右侧同一标签区同时显示关系图与两张 PDF 页面位图，两个视图的实际边界相交。0.5.21 七次恢复均显示 61 个节点，PDF 控件隐藏且没有在视口内呈现位图。三版点击 PDF 后均还原八页文档，视口内两页均完成绘制；再次选择关系图均只显示关系图。三版重新打开该项目时恢复的缓存状态也相同。

## 同机实测

表中每个单元格依次给出 0.5.19、0.5.20、0.5.21。每批预热两轮，取七次中位数。首次反馈计至 WPF ApplicationIdle；完成时间与 UI 线程分配计至 PDF 的延迟定时器、绘制任务及后续布局排空，再扣除相邻空操作。可见控件按与窗口边界相交计数，另核验图节点和视口相交的 PDF 页位图。

| 操作 | 首次反馈（ms） | 完成（ms） | 分配（B） | 可见控件 |
| --- | --- | --- | --- | --- |
| 重开项目，恢复到图 | 279.71／275.57／265.03 | 360.75／359.80／265.26 | 14,621,272／14,594,808／14,280,864 | 55／55／49 |
| 首次点 PDF | 0.93／1.13／8.80 | 0.97／1.11／130.59 | 119,616／119,560／424,352 | 48／48／48 |
| 从 PDF 切回图 | 1.07／1.07／1.10 | 1.06／1.07／1.02 | 85,968／85,912／86,120 | 49／49／49 |
| 关闭关系图回到 PDF | 2.16／2.04／2.05 | 107.72／103.13／117.33 | 83,200／80,992／83,240 | 46／46／46 |
| 重新打开关系图 | 12.06／13.53／10.31 | 12.07／13.13／10.35 | 619,504／619,176／606,664 | 49／49／49 |

修正前恢复时已经绘制 PDF，首次点 PDF 可以复用这两张位图。修正后直到用户切到 PDF 才触发页面绘制，计入产品现有的 100 ms 渲染定时器。按同一轮逐次合计“恢复到图＋首次选择 PDF”，0.5.20 与 0.5.21 的完成时间中位数为 360.90／388.89 ms，分配为 14,714,416／14,705,216 B。切回图约多 208 B；关闭图的分配中位数多 2,248 B，两版样本范围有重叠。当前测量未将这些小差异归因到具体调用点。一批数据只用于同机比较，未测 GPU 和工作线程分配。

0.5.19、0.5.20 构成本场景的历史对照，逐项较优成绩可从前两列数值复核。早期的关系图测量采用 900 × 760 DIP，没有缓存 PDF、窗口重开或光栅完成条件，另见[历史关系标签记录](../relations-tab-20261111/README.md)。

## 复测

将[本场景夹具](fixture.cs.txt)通过[现有 WPF 宿主](../annotation-modes-20261118/Harness.csproj)编译为 Release，使用 `-p:ProductDir=<0.5.19 正式目录>` 和 `-p:Fixture=<夹具绝对路径>`。对每版在其完整发布目录的副本中叠入同一组 `TeXeed.AppTests*`，从仓库根目录运行 `dotnet <副本>/TeXeed.AppTests.dll <新结果目录>`。0.5.19、0.5.20 在末尾另加 `expect-overlay`，仅用于校验旧现象。测试使用仓库的 `.tools/tectonic`，每次生成独立主文稿和 PDF。
