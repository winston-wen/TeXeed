# 排队交接界面性能（2026-11-17）

同一台 Windows 主机、.NET WindowsDesktop 10.0.7、900×760 DIP 屏幕外且不激活窗口，使用 0.5.7 正式发布程序集和本轮功能构建。每项两次预热、七对样本，配对空闲操作、800 ms 草稿保存等待与保存锁；记录 UI 线程分配和可见控件，不包含 GPU 或后台线程。屏幕外窗口与历史可见窗口条件不同，不能把历史结果当作同环境验收。

`panel-offscreen.cs.txt` 与 `../table-cell-viewport-20261117/panel-offscreen.cs.txt` 一致，检查 120 轮、每轮三条长过程记录下的普通输入、变宽、滚动和输入框高度。

`queue-fixture.cs.txt` 创建隔离账号和模拟 HTTP 服务，加载 120 轮会话，在第一轮阻塞时排两条消息，随后放行第一轮并等待第二条真实进入模拟服务。它检查正在执行的轮次、未发送草稿和剩余队列，记录交接耗时及队列可见内容；不调用真实模型，不模拟系统鼠标或输入法。修改前会显示“排队·发送中”和另一条等待消息，修复后只应显示仍在等待的消息；两版功能不同，因此该专项无同功能历史最佳。改前逐次数据为 `before-normal.json`、`before-handoff.json`，程序集和夹具指纹见 `before-fingerprints.json`。

复测示例：以 `Harness.csproj` 的 `ProductDir` 指向对应版本发布目录、`Fixture` 分别设为 `panel-offscreen.cs.txt` 和 `queue-fixture.cs.txt`，编译两个独立宿主；分别传入新的隔离输出目录，串行运行。不要与构建、浏览器或其他测试并行。所有项目和凭据均位于各自输出目录中的隔离 profile。

`handoff-deep.cs.txt` 使用相同 120 轮会话，构造两个待处理项，分别测本地完成并刷新界面、可靠保存完成并刷新，以及单独保存。`deep-intermediate.json` 是尚未包含最终异常数据修复的中间构建各一批；对应程序集和夹具指纹在 `intermediate-fingerprints.json`。本地完成和保存完成的配对分配中位分别为 154,808 和 219,936 B，单独保存为 75,624 B。两种完成操作差额约 65 KB，但这个夹具没有运行请求或整轮交接，不能直接将该差额从端到端的版本差异中扣除。网络、模型、存储环境及后续多次布局均可能影响真实响应；未采调用栈。

最终功能构建的专项逐次数据为 `final-handoff.json`，指纹为 `final-fingerprints.json`。0.5.7／本次交接配对耗时中位数 80.96／81.62 ms，UI 线程分配 5,690,240／6,266,104 B，视口内控件 41／40。最终版等待队列只含一条消息；两版各一批，耗时受调度波动影响，不足以确认小幅差异。每版七个样本中，最终版分配均高于改前样本范围。新增持久保存、轮次恢复去重与及时刷新属于功能差异，调用栈及完整同功能反事实缺失，不能确定约 576 KB 增量的全部来源，也不能认定它均为不可避免成本；本专项性能尚未完全通过。

`intermediate-normal.json` 为连续保存失败和重复 ID 边界修复前的普通阅读样本；与改前四项分配中位数均相同，都是 47 个控件，但不是最终功能构建，不能当作最终程序集的性能验收。`intermediate-handoff.json` 与 `after-handoff.json` 是两次中间专项样本，均不是最终代码；它们与当时的程序集指纹一并保留，不作为历史最佳。
