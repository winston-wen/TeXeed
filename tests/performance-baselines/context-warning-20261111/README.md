# 首轮超窗警示的界面渲染（2026-11-11）

同一 Windows 机器、WPF 900×760 DIP，空会话显示发送中的一轮，在活动列表插入相同的合成警示文字；每次先清除警示，再配对空 `ApplicationIdle` 和插入警示后的 `ApplicationIdle`，分别测 UI 线程托管分配及耗时，热身 3 次、采样 7 次。按旧／新／新／旧顺序串行测量，窗口边界相交估算可见控件。旧版 0.4.7 不会自动显示这条警示，夹具主动添加完全相同的活动，以提供可比的渲染基准；这是新增功能，没有更早同场景历史最佳。

| 版本 | 配对分配中位数 | 配对耗时中位数 | 添加前／后可见控件 |
| --- | ---: | ---: | ---: |
| 已发布 0.4.7（两批） | 均 360,368 B | 5.30–5.73 ms | 均 24／26 |
| 本次功能构建（两批） | 均 360,368 B | 5.34–5.93 ms | 均 24／26 |

两版显示同样警示时的 UI 线程分配没有观察到差异。24→26 是各版本【插入警示前后】的控件数变化，不是跨版本的变化；这两个控件是新增警示内容及其折叠呈现的一部分。只有两批、耗时可能受系统调度影响，不能断定性能完全相同。

这项测量只覆盖警示活动进入可见列表时的 UI 渲染和队列排队校正，不包括后台附件估算、模型网络请求、checkpoint 写入、800ms 草稿保存、GPU 或真实输入法。没有声称整轮真实请求的端到端性能通过；现有 120 轮常规交互历史对照见 `attachments-separated-20261111/`。
