# 排版与 UI 性能

## 排版约定

- 同一阅读流中，同类文字共用字号、实际首字左边缘和文字基线。列表层级、代码行号保留语义缩进。
- 间距按行内、段落、同级条目及分组分别定义，用行高或比例计算；每个间隔由一层负责。
- 折叠时间放在同一文本块中使用自然行距。局部间距调整只应用于指定条目。
- 阅读和过程记录采用紧凑文字层次；工具详情按需创建，代码使用等宽字体和逻辑行号。
- 保留控件虚拟化、节点复用和合并更新。修改后检查真实文字坐标、交互命中与阅读位置。

## 固定简评

每次 UI 改动测量受影响的交互。使用 Release、隔离配置和固定合成资料，前后保持机器、DPI、主题、窗口尺寸及测试程序一致。

```powershell
dotnet run --project tests/TeXeed.AppTests -c Release --no-restore -- --ai-ui-perf-only --output artifacts/ui-before
dotnet run --project tests/TeXeed.AppTests -c Release --no-restore -- --ai-ui-perf-only --baseline artifacts/ui-before/ui-performance.json --output artifacts/ui-after
```

改动前先建立基线。比较发布程序集时，让同一测试程序分别加载对应版本。

AI 合成场景包含 120 轮、1,800 条活动记录，每条引用 2,000 行工具输出；窗口宽度在 900 和 620 DIP 之间切换，高度 760 DIP。热身后记录七次，输出各次样本及中位数：滚动布局、详情展开／收起、缩放耗时，滚动、详情展开／收起、缩放三个阶段的 UI 线程分配量及实际轮次／活动控件数。每个阶段等待到 ApplicationIdle，纳入 Loaded／Render 队列中的校正；0.3.41 及更早记录采用当时的较短统计窗口，不能直接混比绝对值。另记录已创建的 WPF Control 数量，以及按视区和祖先裁剪后仍有面积的可见 Control 数量。

报警条件：耗时超过基线 1.3 倍且增加超过 8ms；分配量超过 1.3 倍且增加超过 256KiB；实际轮次控件超过 12 个。

## 深评

简评报警后保留首次结果，用旧版与新版发布程序集相邻复测。检查热身、异步工作和可见控件数量。字号或密度变化时，可加 `--normalize-typography` 比较相同排版参数，分别记录功能成本与实现成本。

定位退化后优先调整按需创建、虚拟化、节点复用及合并更新。修复后以原基线和原阈值复测。原始 JSON、样本和截图放在忽略的 `artifacts/`，本页记录当前版本结论。

使用 0.3.41 的原统计方法与固定资料，冻结旧程序集，并在临时诊断构建中分别记录校正回调、首行查询、字形读取和坐标变换的线程分配量。关闭编号校正的对照构建只用于归因，正式程序保留校正功能。

| 同一滚动操作 | UI 线程分配量 |
| --- | ---: |
| 关闭编号校正的对照 | 2,199,384 B |
| 0.3.41 | 2,346,144 B |
| 0.3.42，原统计窗口 | 2,226,944 B |

新增 146,760 B 全部随编号校正的启用而出现。五个校正回调合计 142,840 B，其中首行位置查询 48,000 B、字形遍历 94,720 B；后者包含绘制快照 36,240 B、祖先坐标变换 18,240 B，其余为临时矩阵对象、递归闭包和字形处理。该夹具的回答无标题、无公式，排除了字体切换及公式排版成本。其余差额包含校正对象、变换、事件及调度绑定。

普通文字首行直接读取已有绘制数据，跳过后续行和不绘制文字的布局控件。递归传递值类型矩阵，仅在根节点转换到共同坐标；回调复用同一委托。列表、非文字开头及多基线绘制保留精确行位置查询。相同窗口下，新增分配从 146,760 B 降至 27,560 B，消除约 81.2%，相对关闭功能的增量从 6.67% 降至 1.25%。保留部分为实际字形读取、校正对象与事件等成本；不将其视为无法继续降低的理论下限。

### 完整交互复测

测试现等待 ApplicationIdle，将 Loaded／Render 队列中的校正计入对应阶段，并记录详情及缩放的分配量。新旧程序集共用同一测试程序、相同资料、窗口及原报警阈值。更完整的等待改变了历史高度估算的稳定时机，因此以下绝对值仅在本表内比较。

### 排版与回归

九类问句在 800／420 DIP 两种宽度下共 18 项实际字形验收，包括中英文、粗体、代码、仅圈点、无序／有序列表、首行标题和自动换行。独立读取首行文字区域及字形边界，中轴误差均小于 0.001 DIP，与冻结旧版一致；标题、公式位置、行距及折叠回归通过。实际渲染检查中，字号、层级、左边缘、留白和可读性保持原样，未见新增视觉问题。原型的已验收布局及交互保持一致，12 组 JavaScript 回归通过。

原始结果、临时诊断源码、关闭功能的对照、首次报警、三组深评及截图保存在忽略的 `artifacts/ui-0.3.42/`。`idle-comparison.json` 汇总完整阶段比较；补充问句场景用 `--ai-ui-perf-only --with-complex-questions`，标题场景用 `--with-headings`。诊断计数器与关闭功能的代码不进入正式构建。

## 0.3.43 实时阅读状态与行内代码背景（2026-10-30）

实时编号的元素名绑定在控件移入消息列表后失效，回退为微软雅黑 UI；现在显式沿用问句的正文字体，实际拉丁字形为 Times New Roman，常规字重 400。流式段落每次更新都应用与完成状态相同的 25 DIP 行框和 BlockLineHeight，正文入口使用相同的 2 DIP 外边距。生成中两类正文／过程过渡的实际基线距离由约 19.60／31.90 DIP 恢复为 26.84／26.66 DIP，与完成状态一致。

状态呼吸灯由 7 DIP 改为 13 DIP，与状态字号一致；依据状态文字的实际字形指标设置基线。实测中线误差由 −3.705 DIP 降至约 0.0016 DIP。字形测量仅在文字状态更新及加载时执行，动画仍只改变透明度。

文件链接边界的光标框原为整个 25 DIP 行框，背景重复增加内边距后达到 33.73 DIP。代码的装饰留白现在位于链接文本上下文内部，使链接和普通代码均返回实际字体指标，背景统一为 25 DIP，垂直位置一致。字色、单词下划线、文字基线、复制内容及旧批注锚点保持一致；没有增加光标测量调用。

原型按时间顺序展示中途正文与过程记录，采用相同阅读间距和指示灯尺寸；字体简写为空时从实际字体属性构造测量字体，避免带数字变体的元信息被 Canvas 默认字体测量。原型行内代码字号与原生的 14 DIP 一致，文件链接按钮去掉透明边框。

### 性能简评
