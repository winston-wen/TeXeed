# 排版与 UI 性能

## 排版约定

- 同一阅读流中，同类文字共用字号、实际首字左边缘和文字基线。列表层级、代码行号保留语义缩进。
- 间距按行内、段落、同级条目及分组分别定义，用行高或比例计算；每个间隔由一层负责。
- 折叠时间放在同一文本块中使用自然行距。局部间距调整只应用于指定条目。
- 阅读和过程记录采用紧凑文字层次；工具详情按需创建，代码使用等宽字体和逻辑行号。
- 保留控件虚拟化、节点复用和合并更新。修改后检查真实文字坐标、交互命中与阅读位置。

## 固定简评

每次 UI 改动测量受影响的交互。使用 Release、隔离配置和固定合成资料，前后保持机器、DPI、主题、窗口尺寸及测试程序一致。

```powershell
dotnet run --project tests/TeXeed.AppTests -c Release --no-restore -- --ai-ui-perf-only --output artifacts/ui-before
dotnet run --project tests/TeXeed.AppTests -c Release --no-restore -- --ai-ui-perf-only --baseline artifacts/ui-before/ui-performance.json --output artifacts/ui-after
```

改动前先建立基线。比较发布程序集时，让同一测试程序分别加载对应版本。

AI 合成场景包含 120 轮、1,800 条活动记录，每条引用 2,000 行工具输出；窗口宽度在 900 和 620 DIP 之间切换，高度 760 DIP。热身后记录七次，输出各次样本及中位数：滚动布局、详情展开／收起、缩放耗时，滚动 UI 线程分配量及实际轮次／活动控件数。

报警条件：耗时超过基线 1.3 倍且增加超过 8ms；分配量超过 1.3 倍且增加超过 256KiB；实际轮次控件超过 12 个。

## 深评

简评报警后保留首次结果，用旧版与新版发布程序集相邻复测。检查热身、异步工作和可见控件数量。字号或密度变化时，可加 `--normalize-typography` 比较相同排版参数，分别记录功能成本与实现成本。

定位退化后优先调整按需创建、虚拟化、节点复用及合并更新。修复后以原基线和原阈值复测。原始 JSON、样本和截图放在忽略的 `artifacts/`，本页记录当前版本结论。
