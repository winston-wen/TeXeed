# 排版与 UI 性能

## 排版约定

- 同一阅读流中，同类文字共用字号、实际首字左边缘和文字基线。列表层级、代码行号保留语义缩进。
- 间距按行内、段落、同级条目及分组分别定义，用行高或比例计算；每个间隔由一层负责。
- 折叠时间放在同一文本块中使用自然行距。局部间距调整只应用于指定条目。
- 阅读和过程记录采用紧凑文字层次；工具详情按需创建，代码使用等宽字体和逻辑行号。
- 保留控件虚拟化、节点复用和合并更新。修改后检查真实文字坐标、交互命中与阅读位置。

## 固定简评

每次 UI 改动测量受影响的交互。使用 Release、隔离配置和固定合成资料，前后保持机器、DPI、主题、窗口尺寸及测试程序一致。

```powershell
dotnet run --project tests/TeXeed.AppTests -c Release --no-restore -- --ai-ui-perf-only --output artifacts/ui-before
dotnet run --project tests/TeXeed.AppTests -c Release --no-restore -- --ai-ui-perf-only --baseline artifacts/ui-before/ui-performance.json --output artifacts/ui-after
```

改动前先建立基线。比较发布程序集时，让同一测试程序分别加载对应版本。

AI 合成场景包含 120 轮、1,800 条活动记录，每条引用 2,000 行工具输出；窗口宽度在 900 和 620 DIP 之间切换，高度 760 DIP。热身后记录七次，输出各次样本及中位数：滚动布局、详情展开／收起、缩放耗时，滚动 UI 线程分配量及实际轮次／活动控件数。

报警条件：耗时超过基线 1.3 倍且增加超过 8ms；分配量超过 1.3 倍且增加超过 256KiB；实际轮次控件超过 12 个。

## 深评

简评报警后保留首次结果，用旧版与新版发布程序集相邻复测。检查热身、异步工作和可见控件数量。字号或密度变化时，可加 `--normalize-typography` 比较相同排版参数，分别记录功能成本与实现成本。

定位退化后优先调整按需创建、虚拟化、节点复用及合并更新。修复后以原基线和原阈值复测。原始 JSON、样本和截图放在忽略的 `artifacts/`，本页记录当前版本结论。

## AI 原型视觉精修（2026-10-26）

浏览器前后版本共用固定合成资料：50 轮、每轮 6 段正文及 3 条过程记录、每条详情 120 行，初始折叠 10 轮。视区为 1280×900，缩放阶段切换至 620 像素宽。每项热身 2 次、记录 7 次，保留两版各自的排版参数。同步耗时包含 DOM 修改与布局；完成耗时截至两次 `requestAnimationFrame` 后。

| 操作 | 美化前中位耗时 | 美化后中位耗时 |
| --- | ---: | ---: |
| 重绘 50 轮，同步／完成 | 66.4／99.2 ms | 40.3／53.0 ms |
| 首轮折叠再展开，同步／完成 | 135.8／175.7 ms | 100.3／123.6 ms |
| 工具详情展开／收起，同步 | 1.7 ms | 1.9 ms |
| 输入两行草稿，同步 | 5.8 ms | 5.7 ms |
| 滚动布局，同步 | 0.5 ms | 0.5 ms |
| 宽窄视区往返，完成 | 66.3 ms | 66.6 ms |

本次简评未触发“超过基线 1.3 倍且增加超过 8ms”的耗时报警。详情、输入、滚动的完成耗时均约 33ms，包含浏览器帧调度。

挂载轮次／过程记录保持 50／150，详情编辑器按需由 0 增至 1；交互控件总数保持 360。视区及祖先裁剪后的可见控件，宽屏为 25 → 25，窄屏为 20 → 21。两种宽度均无页面横向溢出。

浏览器 `usedJSHeapSize` 的前后占用变化分别为 −7,250,444 B 与 +248,883 B，含垃圾回收时机影响。Node 补充测量固定 HTML 生成并保留 40 份输出，堆增长为 13,057,952 → 13,058,352 B，中位耗时为 0.2166 → 0.2074 ms，输出均为 102,320 B。两项均是内存占用代理；上文原生程序记录的是 UI 线程分配量。

七套 Node 回归通过，包含预览存储隔离、已有会话与草稿保留、批注确认、历史分页、富文本、回答恢复及标签操作。最终生成页中的合成会话、问题、草稿和渲染回答已逐项核对。测试副本、脚本、完整样本、浏览器结果与截图位于 `artifacts/prototype-visual-20261026/`，测量入口为 `bench.html`，原始结果为 `browser-results.json` 和 `node-results.json`。

## AI 原型时间标签与轮次编号（2026-10-26）

时间先于「发送／答复／程序中止／用户中止」标签，轮次数字悬挂在正文左侧，加号与发送按钮共用底色及前景色。折叠后的两行时间仍共用文本块；已有会话、折叠状态和主草稿保留。

以 `e24bb73` 为基线，沿用上一节的 50 轮合成资料、1280×900／620 像素视区，以及热身 2 次、记录 7 次的方法。同步耗时包含 DOM 修改和强制布局。

| 操作 | 修改前同步中位耗时 | 修改后同步中位耗时 |
| --- | ---: | ---: |
| 重绘 50 轮 | 45.1 ms | 45.6 ms |
| 首轮折叠再展开 | 101.7 ms | 104.3 ms |
| 工具详情展开／收起 | 1.5 ms | 1.3 ms |
| 输入两行草稿 | 6.2 ms | 5.8 ms |
| 滚动布局 | 0.6 ms | 0.4 ms |

同步测量未触发耗时报警。本轮浏览器后台标签页的两次 `requestAnimationFrame` 等待约 2 秒；修改后缩放阶段的完成耗时中位数缩短至约 67 毫秒。完成耗时和缩放耗时因调度条件不同，不作前后性能比较，也不代表前台交互响应时间。

挂载轮次／过程记录仍为 50／150，详情编辑器按需由 0 增至 1，展开详情后交互控件保持 360 个。宽／窄视区可见控件保持 25／21，两种宽度均无页面横向溢出。最终 DOM 元素由 4,816 增至 4,916，对应每轮的轮次编号和结束标签两个文本节点容器。

Node 固定生成 HTML 并保留 40 份输出，第二组中位耗时为 0.2291 → 0.2083 ms，输出由 102,320 增至 105,102 B，堆增长为 13,057,952 → 13,842,264 B（+6.0%）。新增编号与标签带来字符串和节点成本；该指标是堆占用代理。浏览器堆占用变化分别为 −9,883,085 B 与 −1,573,613 B，受垃圾回收影响，不能据此计算精确分配量或判断内存改善。

八套 Node 回归及生成页 JavaScript 语法检查通过，新增测试覆盖时间顺序、中止类型和轮次编号。浏览器核对了正文首字与悬挂数字位置、按钮颜色、折叠时间及草稿保留。原始样本、前后副本、脚本和截图位于 `artifacts/prototype-labels-20261026/`，复测入口为 `bench.html`，结果为 `browser-results.json` 和 `node-results.json`。
