同机、同 Edge/WebView2 156、相同视口与固定 120 段资料进行测试：原型使用 1000×820，真实原生宿主在屏幕外使用 1000×800。0 和 60 条评论各做三批，每批热身两次后采七次，计入两帧排队。原型对照修改前 `0be9eb7` 和同夹具历史版本 `74f01c7`；原生历史夹具沿用 0.4.0 的 AiPanel 测试，保留此前历史样本与本次修改前样本。另将 0.4.0 正式源码归档后加相同测试入口，和新版在独立原生控件内分别测纯正文及完整 TeX 外壳。完整外壳包含导言、标题及图片/Bib 引用，但不提供实际图片和 bib 文件，故不涵盖资源读取或图片解码；旧版会把多数命令直接显示，新版则做结构解析，功能成本与实现退化需要区分。原型与原生跨进程数据不直接混比。

### 分配深评和剩余开销

独立原生控件分项测七次重绘，观察后两批：纯正文 0/60 评论旧版约 1.22–1.23 / 2.88–2.94 MB，新版约 1.56–1.63 / 3.13–3.20 MB；完整 TeX 外壳旧版约 1.32–1.34 / 2.87–2.92 MB，新版约 1.71–1.74 / 3.27–3.31 MB。两场景均有约 0.2–0.4 MB 的稳定采样增量，纯正文也存在，不能全部归因于完整 TeX 新功能。对应两帧渲染多数约 33–37 ms、选区约 17–18 ms；原生可见控件 6 / 19，前后不变。首批分配和帧耗时波动较大，采样包含页面和测试调度，不等同精确总分配。

为查明原因，另在离屏 Edge 用相同文本对旧版、优化前候选与优化后渲染器进行三批交替 V8 分配调用栈采样。优化前逐字符扫描的 `inline` 最近栈帧约 0.92–0.94 MB/七次，跳至特殊字符后约 0.087–0.092 MB；作者区间优化后 `spansFor` 约 0.35–0.38 MB，旧版约 1.73–1.78 MB。按该采样口径，优化后纯正文整体约 1.78–1.86 MB，旧版约 2.91–2.96 MB；完整外壳约 2.26–2.28 MB，旧版约 3.02–3.07 MB。新版 `parse` 栈帧仍约 0.40–0.47 MB，旧版约 0.20–0.22 MB；完整文档的 `documentCommand` 另约 0.30–0.34 MB。后者包含识别 TeX 外壳、宏和结构的新功能成本，纯正文 `parse` 增量则可能有可避免的反复扫描或切片开销。调用栈采用最近命名帧归因，且与原生桥接采样口径不同，不能用两者相减推定 WPF 原生分配的来源；原生剩余增量尚未定量拆分。

全部样本、旧版与候选资源、源码 SHA、测试入口和限制见 `tests/performance-baselines/display-041/`、`display-041-historic/`、`display-041-full/` 和 `display-041-plain/`；调用 `verify.cjs`、`verify-webview.cjs`、`verify-profile.cjs` 校验。旧版资源和独立夹具由 Git 归档构建，不包含用户会话。图片/Bib 真实读取、多作者长文和系统输入法不在本次性能夹具内。

## 回答编辑与批注原型（2026-11-06）

原型采用同机、同浏览器和同一 120 轮合成会话，分别测量无标签及保留 60 条历史用户标签。以改动前 `7af94c2` 为相邻对照，三批交错、每批预热两次后采七次，每次记录同步耗时和等待两帧的耗时。字体加载完成后测量；新原型另初始化当前末轮的默认携带状态。测试入口、资源指纹、原始样本和指纹验证见 `tests/performance-baselines/review-prototype/`。

## AI 标题层级编号（0.3.54）

## 用户标签标记与波浪线（0.3.53）

用户标签在选中文本所在行的左侧显示浅金色书签轮廓；同一行的多个标签合用一个图标。提问首行的轮次编号占用悬挂区时，图标移到编号下方。标记不参与正文排版或鼠标命中，随标签增删、会话切换和折叠状态更新；表格横向滚动时，标记仍留在对应行左侧。已有标签也会显示。

新建标签保存少量选文上下文，以便其他章节折叠后区分重复文字。缺少上下文及所属章节信息的旧标签，在回答有折叠章节时暂不绘制图标；跳转时先展开章节并重新定位。展开后若相同选文仍有多处、无法可靠判别原位置，也不绘制图标或执行可能错误的跳转，标签数据和书签入口仍保留。可在目标处重新添加标签。

波浪线仅对从实际布局中测得、未换行的连续汉字段复用宽度；字体、字号、DPI、语言及该段生效的文字格式发生变化时不复用，非默认字体排版特性、混排和换行仍走原有测量。按历史高密度夹具单独对照波浪线优化，连续变宽的分配从 3,616,600 B 降至 3,358,448–3,363,872 B，约下降 7%；详情展开分配 1,423,840 B、可见控件 28 均不变。相对不含波浪线的历史最佳 1,854,424 B，仍高约 81%；该差距包含实现波浪线所需的文字定位成本。样本、冻结源码与方法见 `tests/performance-baselines/wave-optimization/`。268 组 WPF 波线几何对照覆盖多宽度、字体、字号、局部格式和折叠；DPI 变化纳入缓存键，但尚未在跨显示器场景实机验证。

另以同宽同视口的合成会话比较无标签与 31 个用户标签：滚动分配 15,632 → 16,984 B，连续变宽分配 1,621,112 → 1,902,160 B，可见控件均为 20。重排时需重新定位标签；绘制组复用降低了滚动时的额外分配。原始样本及夹具见 `tests/performance-baselines/bookmark-markers/`，单批耗时波动较大，不据此判断速度变化。

## 排版约定

- 同一阅读流中，同类文字共用字号、实际首字左边缘和文字基线。列表层级、代码行号保留语义缩进。
- 间距按行内、段落、同级条目及分组分别定义，用行高或比例计算；每个间隔由一层负责。
