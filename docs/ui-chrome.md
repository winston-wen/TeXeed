# 分隔线、滚动条与编译输出

## 行为依据

0.1.24 实现前查阅了 VS Code 官方源码（2026-09-29）：

- [editorOptions.ts](https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/config/editorOptions.ts)：编辑器默认纵向滚动条与滑块宽 14px，横向高 12px，默认不显示端头箭头。
- [scrollableElement.ts](https://github.com/microsoft/vscode/blob/main/src/vs/base/browser/ui/scrollbar/scrollableElement.ts)：鼠标、滚动和拖动控制显示，延迟隐藏为 500ms，拖动期间不隐藏。
- [scrollbars.css](https://github.com/microsoft/vscode/blob/main/src/vs/base/browser/ui/scrollbar/media/scrollbars.css)：显示过渡 100ms，隐藏过渡 800ms，隐藏时禁用命中；滑块区分普通、悬停、拖动颜色。
- [sash.css](https://github.com/microsoft/vscode/blob/main/src/vs/base/browser/ui/sash/sash.css)：分隔线的可见外观与命中区分离，悬停和拖动时高亮。

采用原生 WPF 实现上述交互，没有引入 WebView 或复制 TypeScript/CSS 实现。
按本项目用户要求，即使鼠标停留在区域内，只要没有新动作也会淡出；鼠标停在滚动条上、捕获拖动期间则保持可见。
WPF 使用 DIP 随 Windows DPI 缩放。为避免自动显隐导致文本重排，编辑器的滚动条槽位保持稳定，仅淡化外观并关闭隐藏滑块的命中。自 0.1.25 起，PDF 使用覆盖式滚动条，视口宽度不扣除单侧槽位；滚动条位于对称的页面外侧留白中，显隐不会改变页面居中或缩放。

自 0.1.28 起，编辑器视口取消右侧和底部的固定内边距，正文直接接到滚动条轨道，避免滚动时出现暗色空白带；左侧和顶部仍保留阅读留白。

## 实现约束

- `ScrollActivity` 监听本区域的鼠标移动、按键、文字输入及滚动；过滤 WPF 在布局／命中变化后合成的位置未变的鼠标移动，避免静止时反复唤出；尊重 Windows 关闭动画的设置。控件卸载时移除监听并停止计时器。
- 半透明小圆角矩形：滑块 2 DIP 圆角，普通／悬停／拖动不透明度分别为 35%／55%／75%，颜色来自当前主题。轨道不透明度 25%。
- 滑块最短 24 DIP，通过 WPF Track 使用的系统度量资源控制。不能再用 `Thumb.MinHeight/MinWidth` 硬撑大滑块，否则其显示尺寸与轨道拖动计算不一致。参见 [WPF Track.cs](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/System/Windows/Controls/Primitives/Track.cs) 的 `ComputeScrollBarLengths`。
- 区域之间只留 2 DIP 分隔列，相邻面板不重复画边框。分隔器命中区宽 8 DIP，覆盖两侧各 3 DIP；悬停／拖动高亮不改变列宽。折叠左栏时隐藏分隔器，由图标轨道绘制单条右边框。
- 编译输出独立模板统一页签背景、选中下划线和内容区域。问题列表和完整日志的滚动条均贴齐编辑区右边缘；文本留白由内容负责，不给滚动条额外留白。

界面回归涵盖两套主题、输入显隐与区域隔离、捕获期间不淡出、窄分隔线命中、长文档展开日志后的滑块首尾边界，以及两个日志页签的滚动条对齐。

## 窗口与缩放（0.1.34）

最大化通过 `WM_GETMINMAXINFO` 使用当前显示器工作区的物理像素边界，不再同时对内容施加固定内边距；全屏使用同一显示器的完整边界。F11 与菜单共用切换逻辑，保存并恢复普通窗口位置、尺寸及最大化状态，隐藏标题栏时 Alt 菜单改在内容左上角弹出。切换提示在 180ms 内淡入、停留约两秒后淡出，不拦截输入。

侧栏最左侧固定 42 DIP 竖向功能轨道，五个功能按钮共用一组控件，折叠只隐藏右侧面板。面板宽度、搜索内容、文件及编辑状态不随折叠重建。

PDF 缩放滑块及百分比显示订阅预览的实际缩放变化，包含滚轮、版心裁切、窗口宽度改变后的自动宽度。百分比保留两位小数，可点击输入；手动操作取消待执行的源码跟随并关闭自动宽度。关闭自动宽度可冻结当前比例；裁边切换保持自动／手动模式，缩放范围为 20%–300%，裁边模式支持到 800%。

## 菜单、全屏与大纲（0.1.35）

菜单栏常驻，Alt 仅切换菜单焦点；窗口重新激活时重申当前宽／窄布局，退出菜单或最小化不隐藏菜单栏。倍率输入明确指定主题的普通文字、选中文字、选区与光标颜色。

全屏通过 [ITaskbarList2.MarkFullscreenWindow](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-itaskbarlist2-markfullscreenwindow) 向 Windows Shell 明确声明；激活时任务栏退到窗口之后。没有隐藏系统任务栏、拦截 Win 键或强制始终置顶；系统仍控制开始菜单与任务栏的激活。

大纲的标题视口使用原有富文本与矢量公式，单行裁切并预留省略号，三角独立占据行尾。单击立即展开／收起，双击撤销第一击的折叠并跳转。右键捕获期间以 45 DIP/s 在完整标题两端往返，每端停留约 600ms；松开、捕获丢失或控件卸载停止移动并复位，内容不滚出原行。左侧五功能轨道统一单击开关面板，移除标题处的三枚折叠／展开图标。

## 大纲长按播放（0.1.36）

左键与右键均支持长按约 400ms 后播放完整标题。左键短按仍展开／收起，双击仍跳转；长按松开不会触发折叠。左键的等待计时器在松开、捕获丢失和控件卸载时取消，播放时暂时关闭标题提示，避免遮挡。

标题的裁切容器使用 Canvas，让富文本以完整自然宽度排版，静止的容器负责裁切；不再让标题自身携带随位移移动的窄布局裁切。尾部文字和行内矢量公式都能滚入视口，往返距离以完整标题宽度计算。回归检查实际渲染的标题末尾，同时覆盖短按、双击、两种按键长按，以及等待和播放期间的捕获丢失。

## 全屏原生区域（0.1.37）

全屏时完全移除 `WindowChrome`，退出后恢复原对象。即使标题高度和边框设为零，WPF 的 [WindowChromeWorker](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/System/Windows/Shell/WindowChromeWorker.cs) 仍会在最大化时把原生 HWND 区域裁到显示器工作区 `rcWork`，使任务栏占用的条带无法绘制；完整窗口尺寸和 Shell 全屏标记不能解除这层裁切。全屏仍使用当前显示器的完整物理边界，并由 Shell 管理任务栏层叠和 Win 键激活。

回归除了 WPF 内容边界，还检查 `GetWindowRgn` 的四角覆盖和 `WindowFromPoint` 在屏幕底部命中的真实窗口，避免仅靠 WPF 离屏截图误判。覆盖普通／最大化窗口进入全屏、最小化后重新激活、菜单退出，以及标题栏和可调整大小行为恢复。

## 编辑器自动换行（0.1.38）

默认开启 AvalonEdit 软换行，按编辑区可见宽度排版；开启时禁用横向滚动，关闭后恢复横向滚动。视图菜单和 Alt+Z 共用开关，窄标题栏菜单也提供同一选项。`WordWrap` 偏好随设置保存，旧配置没有该字段时默认开启。

切换只改变显示行，不修改源文件、源码行号、光标、选择或撤销栈。重排时以原视口中心的源码位置重新定位，换行后的视图跟随、范围高亮和跳转继续使用实际渲染行对应的源码行／列；窗口宽度变化会自动重排。原生编辑器回归覆盖中文与 emoji、重排和禁用横向滚动、选择与撤销保留及宽度变化；界面回归覆盖宽／窄菜单、快捷键、设置重载与源码定位。

## 标题栏顶部与全屏 Alt（0.1.39）

标题栏去掉内部 6 DIP 上边距，顶级菜单与窗口按钮均使用 39 DIP 高度，加上底部 1 DIP 分隔线维持 40 DIP 标题栏。菜单选中背景和按钮命中区域贴齐窗口顶部。

全屏单按 Alt 显示完整标题栏，按当前宽度显示普通菜单或菜单按钮，并保留最小化、还原／退出全屏及关闭按钮；Alt+菜单访问键同时打开对应菜单。再次单按 Alt、Esc（先关闭子菜单）或点击内容区域收起标题栏。点击标题栏按钮不会提前收起它。窗口最小化后恢复仍保持全屏；关闭按钮走原有保存确认和异步清理流程。

显示的标题栏属于客户区控件，全屏仍保持 `WindowChrome=null`，并允许最小化；不重新应用工作区裁切。界面回归检查顶部控件位置、标题栏显隐与按钮命中、实际最小化和全屏关闭，以及标题栏显示和恢复后屏幕底部的原生覆盖。

## 子文件顶部跟随（0.1.41）

视图跟随使用独立的 `ViewportFollowLocation`：源码处于顶部时返回当前文件第 1 行、第 1 列，其他位置仍返回真实视口中央的源码位置。跨越顶部边界会通知跟随，即使中央仍是同一显示行。PDF 按对应页的显示页首对齐，支持裁边／完整页面；光标模式和手动定位维持原来的居中规则。

原生 SyncTeX 读取先验证 UTF-8，失败时采用 Windows 当前 ANSI 编码，避免 TeX Live 生成的中文输入路径被替换为乱码。读取解压数据仍有 64 MB 上限，文件路径仍须属于已加载项目并通过安全检查。回归使用已编译书稿副本验证第一、第二章页首、模式切换和离开／返回顶部，同时检查 UTF-8、ANSI 压缩定位文件的正反向解析。

## 本地预览缓存（0.1.42）

成功发布 PDF 后，在 `.texeed/preview` 同目录写入按主文件区分的缓存记录。源码与本地依赖采用 SHA-256 内容校验，TeX recorder 的 `.fls` 补充静态发现看不到的图片及文件；发行版文件检查大小和时间，编译器检查身份，PDF、SyncTeX 和版心元数据均核对内容。Tectonic 缺少 recorder 时保守扫描本地项目文件，排除 `.texeed`、Git 和虚拟环境。

打开时有效缓存直接恢复 PDF 并启用同步，不再无条件安排编译；重复的自动编译请求也检查缓存。旧版本、失效或损坏的记录不阻止显示上次成功预览，但在更新前关闭源码同步以避免误定位。实时预览开启时后台更新，关闭时等待手动编译。源码变化仍由引擎排版，复用原有辅助文件及 BibTeX/Biber 缓存，不删掉章节来冒充增量结果。失败的新编译作废缓存的“当前”标记，保留原 PDF。

回归覆盖服务／窗口重启、同时间戳源码修改、动态资源、引擎与界面设置、损坏记录／PDF、编译失败、后台更新和原有调度；另以 310 页书稿副本验证缓存恢复。

## 首次同步与渲染优先级（0.1.43）

缓存 PDF 和新编译结果加载时并行预热 SyncTeX 索引，不等第一次源码滚动再开始解析。索引按输入文件、源码行和 PDF 页组织，正向定位从最近源码行向外查找，保留原有行／列权重与原记录顺序；反向定位只检索对应页。索引快照不可变，定位文件改变时重建，项目切换或关闭取消旧预热。

源码定位或 PDF 滚动会使旧视口渲染请求过期；当前不可中断的 PDFium 页面调用结束后，停止旧页面及邻页队列，优先绘制最新视口。保留已有页面图像，继续遵循原来的缩放、裁边、页首和手动定位规则。回归包含大书稿首次切换章节时的定位／渲染计时、章节跟随及索引匹配一致性。

## 编辑标签（0.1.44）

参考本机 Firefox 157.0.1 的标签样式和用户截图，标签为 32 DIP 高圆角胶囊，标题自然宽度，关闭按钮独立占位 20 DIP，图标 12 DIP；选中边框沿用主题的双色渐变。标签控件按文件身份保留，编辑时更新标记而不重建整栏。

关闭按钮和 Ctrl+F4 关闭标签；右键四种批量关闭按目标标签的当前顺序计算，左／右范围不含目标标签。最后一个标签关闭后显示空编辑区，保留项目、预览以及会话中的文档、未保存内容、光标／选择和撤销栈。保存全部不会重开已关闭标签，重新打开文件恢复其编辑状态。

鼠标捕获实现拖动排序，越过系统拖动阈值后不再触发标签单击；边缘停留按计时器浏览，松开或捕获丢失停止。横向 ScrollViewer 隐藏全部滚动条，滚轮和覆盖式双箭头控制位移；固定在视口的透明遮罩只在有隐藏内容的一端渐变。选中新标签时自动确保可见，主题切换同步更新边框和按钮。
