# AI 工作区（0.3.8）

## 会话权限与命令

- 新会话和旧会话未设置权限时均为“完全访问”：Shell 使用当前 Windows 用户权限，能执行任意 PowerShell、Git、脚本、文件操作及网络请求，工作目录默认项目根；这不是仅限项目目录的沙箱，也不自动取得管理员权限。
- “执行前询问”保留自动源码编辑、保存和编译，Shell 确认先显示命令意图、影响范围、工作目录和当前用户权限，展开后查看只读等宽命令全文。可拒绝、允许一次、允许类似，或输入多行其他意见；Ctrl+Enter、提交按钮或再次点击其他意见提交，命令不执行。选择拒绝/允许会丢弃未提交意见。允许类似仅本次会话生效：同目录的简单 git log/status 查询按保守参数白名单归类，其余仅匹配原命令全文；不跨目录授权，也不在重启后保留。确认窗口可关闭，停止会话也会取消等待。
- “只读”只提供目录、源码读取与搜索；宿主同时阻止 Shell、编辑、保存和编译，模型构造未开放的工具名也不能越权。运行期间权限选择锁定，停止后可修改，下轮按新权限执行。
- Shell 每次是独立的非交互 PowerShell 进程，可指定工作目录和 1–600 秒超时。标准输出和错误各保留最多 24000 字符，超出时明确标注截断。停止或超时终止当前进程及子进程；已经产生的改动不会自动撤销。源码编辑器在命令运行期间暂停输入，先安全保存，再同步磁盘文件并保持对话焦点。
- 提示词要求遇到历史脚本、被删文件、以前版本等线索主动用 `git log`、`git ls-tree`、`git show` 查证，包括删除提交的父版本；专用源码工具的文件类型限制不代表 Shell 不能处理其他文件。按任务核对脚本后执行，保留用户未授权删除的资料。

## 0.3.8 决策与操作详情

- Shell 过程行显示命令目的与成功/失败原因；点击展开或收起命令全文与已捕获输出。输出保留原有截断标识，旧版本未保存的命令输出无法补回。
- 需要用户决定实质性方案时，助手可调用 ask_user，给出 2–4 个选项及影响，推荐项置前；用户也可输入其他意见。此工具在只读模式下也可用，不代替 Shell 权限确认。停止请求或切换项目会取消等待。
- 编译失败、取消或结果失效而仍保留缓存 PDF 时，预览 tab 显示 ⚠，悬停说明缓存状态；成功更新预览后清除。
- 自动压缩使用当前模型生成文本摘要，兼容现有登录 Responses 通道；本版不是服务端 /responses/compact。压缩过程和结果显示在输出流中，失败不会清空聊天。

## 0.3.18 原生对话阅读

- 0.3.25 起移除对话页首标题／账户／模型和图标条，标题改在工作区 tab 显示。每个会话对应唯一 tab，可以同时打开多个会话并拖到左右两栏；重复打开定位到已有 tab。标题超过 15 个文字元素（不拆组合字符或 emoji）时追加省略号，悬停显示完整原文。历史管理中改名立即同步到打开的标签，发送自动命名也会更新标签。当前问题提示保持独立的灰色底线。
- 问题和回答使用正文衬线字体，问题支持 Markdown 和 LaTeX。错误公式显示为等宽代码，悬停查看失败原因。发送批注显示带黄色编号及下划线的可点击有序列表；点击后临时预览对应原文，PDF 显示当时的区域截图及页码。
- 主编辑区删除占位文字，使用等宽字体和行号。圈点列表由“圈点 · 数量”打开独立浮层；原位和条目输入支持 Ctrl+Enter 单条发送，保留主草稿及其他待发条目。发送快照可靠落盘后立即移出待发列表，以本轮快照保存；停止或失败也不回填到编辑区，原文、问题和截图仍可在本轮查看。尚未可靠记录的请求保留草稿和圈点。编号每轮从 1 开始。
- 阅读位置按会话保存；向下滚动时顶部提示当前轮的问题与批注；已折叠的问答不显示此悬浮条，折叠时立即隐藏，展开后恢复正常显示。正文中的源码文件链接可打开当前项目只读源码，带行号引用可定位到行。

## 对话呈现

- 加号与权限在左侧，上下文占用、模型、强度与发送在右侧；控件按所选文字收紧，窄面板自动分成两行。
- 问题下方显示“发送时间：绝对时间戳”，答复末尾的空白灰色点线之上显示“答复时间：绝对时间戳”，两处左对齐；移除轮末复用／删除图标与单独的折叠占位提示。双击答复时间或分隔线区域、聚焦后按 Enter／空格展开或收起本轮，轮次和小标题状态按会话保存。折叠后发送时间追加“（已折叠）”，展开时不显示状态字样。停止／失败保留正文、实际结束时刻及“（未完成）”，折叠和重启后仍显示；旧记录缺少答复时刻显示“未记录”。过程逐条显示，各项详情默认收起，不保存展开状态。
- 输出期间在答复末尾显示“思考中”和绿色呼吸灯，禁止折叠尚在输出的轮次；完成后替换为答复时间。动画只改变透明度，隐藏或结束输出后释放动画时钟，关闭系统界面动画时使用常亮绿点；呼吸不改变对话布局。
- 操作行使用浅底色，内外纵向间距缩减；“已发送”不再单独占一条过程。AI 设置移入对话页右上方，使用与预览设置相同的矢量齿轮。
- 上下文使用率保留一位小数，按最近一次模型请求服务端返回的 input_tokens + output_tokens / 模型目录 context_window 计算，不累加各轮费用 token；切换模型不套用另一模型的占用率。缺少窗口大小或用量时不伪造百分比，显示“—”及具体原因。
- 推理选项“默认·高”等来自模型目录的 default_reasoning_level，表示省略 reasoning.effort 后采用服务端声明的默认值；目录没给出时显示“服务端默认”，不把它说成固定中或高。选具体强度时明确发送对应 effort。

## 使用

1. 打开项目，点标题栏最末的 **AI**（Alt+A）菜单选择 **AI 对话** 新建会话。**AI 设置** 打开设置 tab，**AI 历史** 中提供按最后一次发送时间排序的近期五条，以及 **管理 AI 会话历史**。各 tab 均可关闭、跨栏拖动，重新打开会话保留问题、草稿和阅读位置。
2. 从 AI 菜单选择 **AI 设置** 进入独立设置 tab，点 **Continue with ChatGPT** 在系统浏览器授权。新增账号用“添加账号”；下拉列表可切换已保存账号/工作区。登录后从账号提供的模型列表选择模型。
3. API Key 是可选备用连接，勾选后单独使用 OpenAI API 额度，不会在 ChatGPT 用量耗尽时自动切换计费。Key 输入使用密码框，保存后清空输入框。
4. 点击左边栏的铅笔与 AI 合成图标 **AI 圈点**。指针变成 Windows“帮助选择”。左键单击标记点位；长按或拖动选择源码句子/PDF 区域，松开后立即进入对话编辑栏，无须再次确认。编辑区右键保留常用编辑命令；预览区不再显示右键菜单，以免干扰右键双击返回源码。
5. PDF 框选可跨页，靠近上下边缘自动滚动。再次点击侧栏按钮、右键双击、Esc 均可退出圈点；编辑区圈点模式下右键菜单延迟至双击时间后打开。缩放、换 PDF、隐藏预览取消尚未完成的框选，已收集条目保留。
6. 对话页采用上方消息区、下方固定编辑栏。可直接输入问题，或在圈点条目上填写单独说明；空白条目可使用下方统一问题。Enter / Shift+Enter 均换行，只有 Ctrl+Enter 发送，暂不提供配置项；中文输入法确认候选不发送。发送输入内容和勾选条目，未勾选条目不发送。
7. 发送后立即清空输入框，可继续写下一条草稿；本轮完成或停止不清除新草稿。回复逐步显示，进展说明与各项操作按时间排列，最后是独立的最终答复。支持“停止”，同时取消本轮编译；此前已经完成的修改保留。断流、取消、权限或额度错误不会标为成功，过程与问题仍保留，可继续输入问题或重发待提交批注。再次发送是新请求，可能再次消耗额度。

8. 输入栏的模型/推理强度下拉框可直接切换，与 AI 设置同步并保存。打开已登录的 AI 页会自动读取模型目录；输入栏左下角“＋ → 刷新模型”可手动刷新，该菜单也可添加问题、全选条目、清理完成条目或打开设置。发送、停止与加号使用居中的矢量图标，不再显示快捷键底行和省略号菜单。推理选“默认”时省略 effort，让服务决定；其余选项写入请求的 `reasoning.effort`。账号目录的支持等级与公开 Responses 参数取交集，未知 API 模型仅提供默认。
9. **管理 AI 会话历史** 打开非模态工作区 tab，按标题、问题或回答搜索；单击标题打开，双击原位改名，F2 改名／Enter 打开也可用。仅复选框控制批量选择，全选跳过已打开会话，筛选与翻页保留其他所选。管理页不显示滚动条，使用上一页、下一页、页码跳转及滚轮翻页；高度决定每页行数，调整大小保留首个可见标题。已打开会话显示“已打开”，禁用删除选择并提示“会话窗口已打开，关闭后才能删除”。改名不改变近期发送排序。Ctrl+F 查找当前消息，Esc 收起；双击答复时间展开或收起本轮。

10. 会话和窗口一一对应，每个会话独立保留消息、草稿、阅读位置、权限与本次审批记录。切换标签不会停止其他会话的输出；关闭会话标签时停止并保存该会话，其他会话继续运行。共用单一有序写入通道，恢复日志按会话分开，旧版单文件恢复日志仍兼容。项目切换或退出会停止并保存所有会话；同时修改同一项目时原有源码版本检查和工具互斥仍生效。已打开或正在关闭保存的会话不可删除；先关闭对应标签，再从历史管理删除。旧版单一对话自动迁移为历史会话，保留内容。旧空回答标明未完成，不自动合并问答。


## 0.3.5 项目发现与完成任务

- 首次发送有效问题时立即生成、显示并保存标题，不等待网络回答结束；取消或失败仍保留标题，自定义标题不会被覆盖。
- 请求开始前自动提供有界的工作区目录资料，包含当前入口、引擎、载入警告以及未引用模板、样式和资源。`list_directory` 可按目录、深度与页码继续查找；`read_source` 和 `search_source` 支持未被入口引用的 TeX 源码、README 与构建说明。0.3.7 起可按会话权限通过 Shell 执行脚本。
- 工作规则要求辨认入口、模板与共享定义，复用项目格式，实际编辑后保存和验证；不通过删除正文、注释缺失引用、伪造章节或大改字体版式来制造“编译成功”。无法取得的源文件或环境依赖应具体报告。
- `compile_project` 的 `entry_file` 为空时编译当前默认入口，也可指定根目录内已有的 `.tex` 包装文件。指定入口不改变默认主文件；结果明确标识实际入口，不能把包装文件通过描述为默认片段已能独立编译。
- 流式协议按消息及内容块补齐终态，合并遗漏的工具调用；只有进展说明的响应最多继续两次，仍无最终答复便报告未完成。成功修改后若缺少后续编译尝试，仅提醒一次完成用户允许的验证；用户禁止编译或存在阻碍时应如实说明。
- 工作提示词保存在 `src/TeXeed.App/AI/AiAgentPrompt.cs`，可直接审阅。0.3.5 使用用户授权的 Sol / DeepSeek 与四个真实项目副本验证，另用本机 Claude Code 做同题只读对照；详见 [评估记录](agent-evaluation-0.3.5.md)。DeepSeek 适配与读取本机 Claude 配置仅存在于显式运行的测试工具，发行应用的账号连接行为未改变。

## 0.3.4 直接编辑与编译（保留）

- 请求修复、改写或排版时，助手默认读取当前源码，使用工具直接修改，保存并用项目已配置的 TeX 引擎编译，再根据真实诊断继续修复。最终答复概述修改与验证结果，不要求用户复制整段源码。只要求解释或审阅时不应修改文件。
- 提供 `replace_source`、`create_source`、`save_project` 和 `compile_project`。替换要求先读取文件、校验内容指纹并唯一匹配原文；用户在读取之后的新编辑不会被覆盖。保存沿用原编码及外部磁盘变更检查，编译期间内容变化会报告结果过期。
- 每个文件在本轮首次替换前备份其编辑内容至 `%LOCALAPPDATA%\TeXeed\ai\backups`（设置 `TEXEED_HOME` 时在该目录的 `ai\backups`），相邻 JSON 记录原路径。替换进入编辑器撤销栈，保存和编译之后仍可 Ctrl+Z 撤销。
- 专用源码工具仅操作当前项目源码；可新建 `.tex`、`.bib`、`.sty`、`.cls`，不覆盖已有文件。专用工具拒绝越界路径和符号链接；其他文件及命令由 0.3.7 的 Shell 和会话权限处理。切换项目会使旧工具会话失效。
- 每轮保存带时间戳的说明、操作及最终回复；旧版只有问答的历史仍可读取。0.3.3 使用模拟模型和真实 Tectonic 验证修复闭环；后续真实模型验证见版本评估记录。

## 0.3.3 阅读与稳定性修复（保留）

- 回答采用 Markdig 解析为原生 WPF Markdown：标题、粗体/斜体/删除线、嵌套列表、引用、表格、围栏代码、行内代码、链接。支持选择和复制；生成过程中增量显示原文，整轮结束后统一排版 Markdown 和公式，避免为尚未完整的公式反复排版。原始 HTML 不执行，远程图片不自动加载，图片保留替代文字。
- 流式接收和 JSON 处理在后台运行，UI 每 200 ms 合并刷新，避免逐字重设全文并积压滚动任务。单轮最多接收 20 万字符；用户向上阅读时不强行滚到底部。
- 历史使用带集合通知的独立视图集合，追加追问复用已渲染回答；请求历史与圈点绑定使用快照。可见 WPF 控件回归覆盖连续三轮逐字长回答、重复发送、取消和重试。
- 选区故障的直接原因是原 WPF Adorner 模式叠加 100% 不透明选区，把文字覆盖。启动时为普通文本框与密码框启用非 Adorner 绘制，富文本选区使用 35% 透明度。搜索框、设置、可编辑下拉框、问题、日志和 Markdown 均使用主题选区资源；源码编辑器保留原选区。
- 深浅主题分别验证 TextBox、PasswordBox、MarkdownView 实际渲染像素，普通输入框的选中字色/底色及系统失焦选区对比度至少 4.5:1。
- 0.3.3 回归使用模拟服务，未向真实模型发送问题；无法仅凭现有日志确认用户此前每一次卡崩的唯一原因。

## 选区和上下文

- 源码圈点保存收集时的文本、相对路径、行号、UTF-16 偏移和文件 SHA-256。点位文本为空，由 AI 按文件/行号读取上下文；长按或拖动按句子边界收集文本。
- PDF 保存原色 PNG、指纹、1 起始页码及纸张左上原点的 SyncTeX/PDF 点坐标。单击另保存精确点位与附近截图；跨页分开保存，压缩纵向空白分段反映射，旋转和 CropBox 通过现有坐标变换处理。
- 框选最大 1600 × 2400 DIP、3 页、16 个压缩区块；每个条目 PNG 合计不超过 8 MB。渲染使用每页 400 万像素预算，不生成整个文档截图。
- 单个源码条目最多 4 万字符；一批最多 20 个问题、8 万字符和约 18 MB PNG。每个项目最多保留 100 个条目、约 32 MB 截图。
- 提交时固定问题和圈点快照；`project.list_files`、`search_source`、`read_source` 每次读取当前项目编辑内容，包含未保存修改。AI 通过这些工具定位 PDF 对应源码；定位不保证成功，找不到时应明确说明。
- 工具绑定当前项目会话，检索结果与读取行数有界，每次回答最多 40 次工作循环；源码/PDF/日志/工具内容均作为资料对待。未接入工作区的独立宿主仅提供只读工具。
- 长会话自动压缩：使用当前所选模型的低推理请求生成工作状态摘要，按 token 预算预留上下文空间（默认在模型目录窗口的 75% 触发，未知窗口按 128000 tokens 预算）；有服务端用量时以该请求的输入与输出占用为基线，再估算新增工具结果。没有用量时保守估算文本 token；估算不是精确分词。取消 96000 字符固定上限，百分比仍明确表示最近一次模型请求的实测用量。保留近期问答和当前问题，较早记录分块总结；工具循环中也会压缩。摘要与所覆盖轮次的指纹按会话保存，删除/改变历史后自动失效。压缩失败则停止本次请求并保留原文，不静默丢弃。压缩会消耗模型额度，聊天界面保留完整记录。旧图片不会自动重发；当前附图重新附在摘要后，不把 base64 当文字总结。
- 只携带当前对话的历史，其他对话的消息/圈点不进入本次上下文。项目 JSON 使用 Conversations/ActiveConversationId 保存，不重复序列化活动会话媒体。
- 问题和回答保存在 `%LOCALAPPDATA%\TeXeed\ai\projects`，以项目主文件完整路径的哈希隔离；`TEXEED_HOME` 设置时保存在其 `ai` 子目录。文本/截图收集本身不发送网络请求。登录、模型刷新以及提交会连接 OpenAI。

## 认证实现与限制

采用 OpenAI 公开的本地/open-source Sign in with ChatGPT 流程：系统浏览器、127.0.0.1 回调、state、PKCE S256 和 OIDC nonce；验证 OpenAI JWKS 签名、issuer、audience、时间、身份与额度授权 scope。每个安装保留稳定 host ID，各账号保留独立 issued client ID。登录依赖该账号/工作区允许第三方应用使用 ChatGPT 计划额度。

Access/refresh/ID token 与 API Key 使用 Windows DPAPI CurrentUser 加密，原子更新并通过文件锁串行化刷新。退出尝试撤销刷新令牌并清除本机令牌，保留非令牌账号/客户端映射供重新登录；网络原因未确认远端撤销时会说明，可在 ChatGPT 设置断开应用。不会读取 Codex、浏览器或其他应用的登录凭据。

HTTP Responses 使用 `store:false` / `stream:true` 和命名空间工具，客户端自行维护历史。仅收到 `response.completed` 才完成批次。API Key 为单独选择的备用模式。

0.3.1 在用户授权下使用已保存的 ChatGPT 连接做了 6 次 Luna 推理请求（本版本上限 20），涵盖简单文本、历史与源码检索。确认并修复了终止事件 output 为空导致漏掉已完成工具调用的问题：收集 `response.output_item.done`，执行本地工具后续接，纯空响应不再标为已回答。错误显示 HTTP 状态、服务错误码和请求编号，并隐藏凭据形态的内容。

真实测试只发送生成的 hello 源码和简单问题，未发送用户文档。模型/额度以账号实际返回为准。查看本机 Claude 插件的可访问界面和公开样式作为布局参考；computer-use 截图采集超时，未向 DeepSeek 发送消息。

0.3.2 查询实际账号模型目录，读取 supported_reasoning_levels。使用 1 次 Luna 请求验证显式 low 推理参数，得到正常回答；未发送用户文档。配置、加密凭据和对话 JSON 的原子替换遇到 Windows 短时文件占用时最多等待 240 ms 后重试，保留原文件直到替换成功。
